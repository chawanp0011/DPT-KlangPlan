วันที่ทำ 3 พ.ย. 2569 สถานะ: เอกสารวางแผน ยังไม่ได้เขียนฟีเจอร์ใหม่ ข้อมูลในระบบทั้งหมดเป็นข้อมูลตัวอย่าง ไม่ใช่ข้อมูลจริง

0. ฐานที่ใช้และข้อควรรู้

  • โปรเจ็คนี้คัดลอกมาจาก ERP-Gov (ไม่รวม .git) ต้นฉบับไม่ถูกแก้ ตอนนี้ ยังเหมือนต้นฉบับทุกไบต์ (ไฟล์ Prototype.html ที่ build ใหม่เท่ากับของเดิม)
  • คำว่า "มีแล้ว" ในเอกสารนี้ = มีหน้าและตรรกะในต้นแบบ ERP-Gov ด้วยข้อมูลตัวอย่าง ไม่ได้แปลว่าตรงตามระเบียบจริง และการเชื่อมระบบภายนอก (GFMIS, e-GP, สงป., KTB, Smart HR, น้องก่อ) ทั้งหมดยังเป็นการจำลองหรือยังไม่มี (ตาม README_ERP-Gov.md)
  • ผมอ่านโค้ดเพื่อยืนยันว่าหน้าไหนมีอยู่ในต้นฉบับ แต่ ยังไม่ได้ทดสอบฟีเจอร์เทียบกับเอกสารเหล่านี้ทีละข้อ ช่องสถานะจึงเป็นการประเมินจากเอกสารและโค้ด ไม่ใช่ผลทดสอบ
  • ใช้ต่อจาก ตรวจสอบสิทธิ์กองคลัง.md (เทียบหน้าที่กับบทบาท/สิทธิ์ไว้แล้ว) ไม่ทำซ้ำ ที่นี่เพิ่มเฉพาะด้านที่เอกสารสามฉบับนี้เพิ่มมา

2. ตารางช่องว่าง: หน้าที่กองบริหารการคลัง เทียบ ERP-Gov

ความหมายคอลัมน์ "แนวทาง": ใช้ซ้ำ = ใช้ของเดิมได้ตามที่เป็น, ปรับ = มีของเดิมแต่ต้องแก้/เพิ่ม, เขียนใหม่ = ไม่มีในต้นฉบับ, ยังไม่ทำ = ตัดออกจากต้นแบบรอบนี้ (เหตุผลระบุ)

#หน้าที่ / ความต้องการที่มาใน ERP-Govแนวทาง
1สารบรรณ ธุรการ งานพิมพ์ ระบบเอกสารอิเล็กทรอนิกส์ รับ-ส่งภายในและภายนอกxlsx ฝ่ายบริหารงานทั่วไป ข้อ 1, 9 / A3 โมดูล 12ไม่มี (มีเฉพาะรับเอกสาร OCR ที่ P6 ตาม ตรวจสอบสิทธิ์กองคลัง.md)เขียนใหม่
2ทะเบียนคุมงบประมาณรายจ่ายประจำปี ทะเบียนคุมงบประมาณxlsx ข้อ 2 / งานบริหารงบประมาณ ข้อ 9B7 B8 มี (เฉพาะ fin, finhead ทำได้แล้ว)ใช้ซ้ำ/ปรับเล็ก
3ทะเบียนคุมใบสำคัญเบิกจ่ายจนถึงวางฎีกา (ติดตามสถานะทุกขั้น) และ Google Sheet ติดตามการเบิกของกองคลังxlsx ข้อ 3 ฝ่ายทั่วไป, ฝ่ายตรวจสอบ งาน 1 ข้อ 7, งาน 2 ข้อ 3 / MoM พี่ปุ๊กF3 ใบขอเบิกมีขั้นตรวจและกลุ่มตรวจ 1/2 แล้ว แต่ยังไม่มีหน้า "ทะเบียนคุมเอกสารเบิก" ที่ไล่สถานะรับพัสดุ ตรวจ อนุมัติ คีย์เบิก เบิกจ่าย แยกงานก่อสร้าง/ซื้อจ้าง/ซื้อทั่วไปปรับ (เพิ่มหน้ามองรวมและสถานะตามลำดับ ใน MoM)
4แยกบทบาท บัญชี / การเงิน / บริหารงบประมาณ ออกจาก finxlsx ทั้งกอง / ตรวจสอบสิทธิ์กองคลัง.md ข้อ ก ส่วนที่เหลือfin บทบาทเดียว (มี vchk1, vchk2 แล้ว)ปรับ (ต้องรื้อเงื่อนไข ROLE === "fin" กว่า 40 จุด ตามเอกสารเดิม)
5ตรวจใบสำคัญ งาน 1 และ งาน 2 แยกตามชนิดงบและวงเงิน 100,000 บาทxlsx ฝ่ายตรวจสอบใบสำคัญมีกฎกลุ่มตรวจ 1/2 แล้ว ใช้ได้เฉพาะใบที่ผูกสัญญา ใบชนิดอื่นไม่เก็บชนิดงบปรับ (เก็บชนิดงบในใบขอเบิก)
6ติดตามผลและแก้ข้อทักท้วง สตง./ตรวจสอบภายใน พร้อมมาตรการป้องกันซ้ำxlsx ตรวจสอบงาน 1 ข้อ 9, งาน 2 ข้อ 5, บัญชี ข้อ 14F8 มีข้อทักท้วง (ตามเอกสารเดิม)ใช้ซ้ำ (ตรวจว่าครอบคลุม "มาตรการป้องกัน")
7ทำบัญชี งบทดลอง รายงานการเงินประจำปี ต้นทุนต่อหน่วย ปรับปรุงบัญชีxlsx กลุ่มงานบัญชี ข้อ 1-12F7 F8 บางส่วน, B9 ต้นทุนต่อผลผลิต เปิดให้ fin แล้ว ไม่ลงสมุดบัญชีเต็มรูปแบบใช้ซ้ำ/ยังไม่ทำส่วนบัญชีเต็ม (ทำใน New GFMIS Thai)
8โอนเงินจัดสรร ส่งเงินจัดสรรให้ส่วนภูมิภาคxlsx งานบริหารงบประมาณ ข้อ 1, 3B7 โอน/ปรับเปลี่ยนมี ส่วน "ส่งเงินจัดสรรให้ภูมิภาค" ไม่ชัดปรับ
9กันเงินเหลื่อมปี ขยายเวลาเบิกจ่าย เงินกัน เงินพับ ผูกพันใหม่/เดิม ดึงจาก GFxlsx งานบริหารงบ ข้อ 8 / ฝ่ายการเงิน ข้อ 1 / MoM พี่ใหญ่B8 เงินกันเหลื่อมปีมี; ผูกพันมีในข้อมูลงบ; "ดึงจาก GF" ทำได้เพียงนำเข้าไฟล์จำลอง ไม่มีเงินพับปรับ

4.1 Project ID คืออะไร (ผู้ใช้สรุป 3 พ.ย. 2569 ฉบับล่าสุด)

Project ID = รหัสของ "รายการจัดซื้อ" หนึ่งรายการ ออกอัตโนมัติจากระบบ DPT ทุกการจัดซื้อต้องมี (รวมงานที่ไม่ผ่าน e-GP เช่น จัดซื้อเล็ก เงินเดือน) เลข e-GP เป็นข้อมูลที่ผูก (mapping) ภายหลัง หลังส่งเรื่องเข้า e-GP แล้ว ฉบับก่อนหน้าที่ผมเสนอว่าเป็นรหัสระดับโครงการงบ ถูกแทนที่ด้วยข้อนี้

```

รายการจัดซื้อ = DPT Project ID (ออกอัตโนมัติ ตอนสร้างรายการ ก่อนส่ง e-GP)

|- สถานะเลข e-GP: ยังไม่ส่ง -> ส่งแล้ว (รอเลข) -> ผูกเลข e-GP แล้ว (บันทึกวันที่/แหล่งที่มา/ผู้ผูก)

|- แถวงบประมาณ (หลายแถว): รหัสงบประมาณ GFMIS + แหล่งเงิน + ปีงบ + จำนวนเงิน + ลักษณะงบ ผูกพันใหม่/เดิม/เงินกัน

|- สัญญา (หลักประกัน แก้ไขสัญญา งวดงาน) -> ฎีกา/ใบเบิก -> ผลเบิกจ่าย -> เงินกัน/เงินพับ

`- ผูกกับ "โครงการ/ผลผลิตตามงบ" (ฝั่ง eBud/GF) เพื่อรวมยอดและทำแผน-ผลเทียบงบ

```

ผลที่ตามมา:

  • ตอนสร้างรายการ ยังไม่มีเลข e-GP: ช่องเลข e-GP ว่างและมีสถานะ "ยังไม่ผูก" หลังส่ง e-GP แล้ว ผู้ใช้หรือไฟล์นำเข้ากรอกเลขมาผูกภายหลัง ระบบเก็บประวัติการผูกและแก้ไขได้ โดย Project ID ไม่เปลี่ยน
  • คำถามเรื่องหนึ่งเลข e-GP ผูกหลาย Project ID จึงเปลี่ยนความหมาย: เมื่อ Project ID คือรายการจัดซื้อและ e-GP หนึ่งโครงการคือการจัดซื้อหนึ่งรายการ ความสัมพันธ์ปกติคือ 1 ต่อ 1 ระบบควรเตือนเมื่อเลข e-GP เดียวถูกผูกกับ Project ID ที่สองและบังคับให้ยืนยัน (กรณี e-GP รวมหลายรายการเป็นโครงการเดียว หรือแตกหนึ่งรายการเป็นหลายโครงการ เป็นข้อยกเว้นที่ผู้ใช้ต้องบอก)
  • ความเสี่ยงที่รับรู้: ใน e-GP มีแถวงบหลายแถวต่อโครงการ ดังนั้นแถวงบจึงอยู่ใต้ Project ID (ตามผังด้านบน) ไม่ใช่ที่ระดับเลข e-GP
  • ห่วงโซ่ตามบันทึกประชุม ebud --> GF --> eGP ===> Project_id และ A3: ห้ามใช้รหัส GFMIS เป็นกุญแจ
  • ตอบแล้ว (3 พ.ย.): Project ID ผูกกับรายการที่ eBud จัดสรรมาให้ ตั้งแต่ตอนเลือกรายการนั้นมาจัดซื้อ (จุดสร้างคือการเลือกรายการที่ได้รับจัดสรร) และรอบนี้ทำเพื่อให้เห็น flow งานจัดซื้อและติดตามจนครบลูป (ตั้งแต่รายการที่ได้รับจัดสรร, จัดซื้อ, ส่ง e-GP, ผูกเลข, สัญญา, เบิกจ่าย, ผลเบิก)
  • ยังไม่ทราบ (ผู้ใช้ตอบว่ายังไม่ทราบ): รายการเดียวที่คร่อมหลายโครงการงบ ในต้นแบบรอบแรกยังไม่รองรับ (1 Project ID ผูก 1 รายการจัดสรร) บันทึกเป็นข้อจำกัด
  • รูปทรงเลข: ตอบแล้ว "ให้ auto ไปก่อน" ต้นแบบออกเลขอัตโนมัติด้วยรูปแบบสมมุติที่ผมกำหนดเอง (เช่น ตัวอักษรนำ + ปีงบ + ลำดับ) แยกเป็นจุดตั้งค่าจุดเดียว เปลี่ยนภายหลังได้ เมื่ออธิบดีตัดสิน (A3 Q-01) รูปแบบนี้ไม่ใช่รูปแบบจริงของ DPT

#### ผลอ่านคู่มือ e-GP (ใช้ประกอบ)

อ่านจาก 00002693.pdf (คู่มือบันทึกข้อมูล e-GP เพื่อรองรับมาตรการเร่งรัดเบิกจ่าย กรมบัญชีกลาง) และคู่มือ e-GP วิธีเฉพาะเจาะจง ไฟล์ดึงข้อความไม่ได้ ผมอ่านจากภาพเฉพาะหน้าที่เกี่ยวข้อง ประมาณ 10 จาก 143 หน้า
