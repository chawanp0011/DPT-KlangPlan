# Fisko-KlangFinance

ระบบต้นแบบสำหรับ **กองคลัง (กองบริหารการคลัง) กรมโยธาธิการและผังเมือง** ข้อมูลทั้งหมดเป็นข้อมูลตัวอย่าง ไม่ใช่ข้อมูลจริง

## สถานะตอนนี้ (3 พ.ย. 2569)

- โครงโปรเจ็คคัดลอกมาจาก `Fisko-ERP-Gov` (ไม่รวม `.git`) ต้นฉบับไม่ถูกแก้
- **รอบ R1 ถึง R9 ทำครบแล้วทั้ง 9 รอบ** (ฝั่งของใหม่ของโปรเจ็คนี้ ดูหัวข้อแต่ละรอบด้านล่าง) ทั้งหมดเป็นต้นแบบข้อมูลตัวอย่าง สูตร อัตรา เกณฑ์ แบบหนังสือ และรูปแบบไฟล์นำเข้าเป็นค่าสมมุติที่ต้องยืนยันก่อนใช้จริง การเชื่อมระบบภายนอกทั้งหมดยังเป็นไฟล์หรือพิมพ์เอง
- **Full sweep ผ่านครบหลังจบ R9 (3 พ.ย. 2569): 15,763 รายการ ไม่มีข้อผิดพลาด (100 วินาที)** ต้นฉบับ Fisko-ERP-Gov รายงานไว้ 12,625 รายการ ส่วนต่างมาจากหน้าใหม่ที่เพิ่มในโปรเจ็คนี้ การทดสอบนี้ตรวจการแสดงผลทุกบทบาทและการเดินเดโม ไม่ได้ตรวจกฎของฟีเจอร์ใหม่ทีละข้อ ซึ่งทดสอบแยกตามหัวข้อ "ทดสอบ R*" ของแต่ละรอบ
- README เดิมยังอยู่: `README.md` (Fisko), `README_Fisko-ERP-Gov.md` (ส่วนที่ต่อยอดเป็น 8 โมดูล) ใช้อ้างว่าอะไรมาจากต้นฉบับ
- เอกสารใหม่ของโปรเจ็คนี้:
  - `สรุปทั้งโปรเจ็ค_Fisko-KlangFinance.md` (และ `.html`) สรุปทั้งโปรเจ็คในเอกสารเดียว เริ่มอ่านที่นี่

  - `MoM_2026-11-02_สรุป.md` (และ `.html`) สรุปบันทึกประชุม 2 พ.ย. 2569
  - `ตรวจสอบสิทธิ์กองคลัง.md` (ยกมาจากต้นฉบับ) เทียบหน้าที่กับสิทธิ์ในระบบ

## รอบ R1: Project ID (เขียนใหม่ในโปรเจ็คนี้)

ไฟล์ใหม่ `src/js/92-klang-projid.js` และแก้เล็กน้อยที่ `src/js/60-procurement.js` (ออก Project ID ตอนเพิ่มรายการในแผนจัดซื้อ) กับ `src/js/00-core.js` (DATA_V 39 เป็น 40) เมนูอยู่ในแอป Fisko Procurement กลุ่ม "Project ID"

| หน้า | ทำอะไร |
|---|---|
| PJ1 ทะเบียน Project ID | Project ID ออกอัตโนมัติ 1 รหัสต่อรายการจัดซื้อในแผน (รูปแบบ `PJ-ปีงบ-ลำดับ` เป็น **ตัวอย่างของเรา** ไม่ใช่รูปแบบจริงของ DPT ตั้งที่ `PID_FMT` จุดเดียว) บันทึกว่าส่ง e-GP แล้ว ผูก/แก้เลข e-GP ภายหลัง (1 เลขต่อ 1 Project ID ซ้ำไม่ได้ แก้ต้องมีเหตุผล) แท็บ "ครบลูป" แสดง 8 ขั้นตั้งแต่ได้รับจัดสรรจนอนุมัติเบิกจ่าย และแท็บประวัติการผูก |
| PJ2 แถวงบประมาณ GFMIS | หลายแถวต่อ Project ID (ปีงบ รหัสงบประมาณ แหล่งเงิน จำนวนเงิน) เตือนเมื่อผลรวมไม่เท่าวงเงิน |
| PJ3 นำเข้าไฟล์ | วาง/เลือก CSV หรือ Tab ตรวจก่อนนำเข้า แถวผิดถูกข้าม มี 2 ชนิด (เลข e-GP ที่ได้หลังส่ง, แถวงบ GF) แยกตัวตรวจและตัวนำเข้าไว้ให้เปลี่ยนเป็น API ได้ภายหลัง |

สิทธิ์: `proc`, `prochead`, `fin`, `finhead` ผูกเลข/แก้แถวงบ/นำเข้าไฟล์ได้ บทบาทอื่น (รวม `plan` ของกองแผน) ดูอย่างเดียว บทบาทหน่วยงาน (`div`, `divhead`) เห็นเฉพาะรายการของหน่วยตน กองแผนงานใช้บทบาทเดิมของ Fisko ตามที่ผู้ใช้กำหนด

**ข้อจำกัดที่รู้:**
- รูปแบบไฟล์นำเข้า e-GP และ GF เป็นข้อสมมุติของเรา ยังไม่เคยเห็นไฟล์จริง
- รายการเดียวที่คร่อมหลายโครงการงบ ยังไม่รองรับ (1 Project ID ต่อ 1 รายการจัดสรร)
- เลข e-GP ที่ถูกบันทึกจากหน้าเดิม (นำเข้าสถานะ e-GP ที่ P-หน้าเดิม หรือแบบฟอร์มในแฟ้มจัดซื้อ) จะแสดงเป็น "ผูกแล้ว" แต่ไม่ลงประวัติการผูก ของ R1
- ขั้นในแท็บ "ครบลูป" อ่านจากข้อมูลตัวอย่างใน Fisko (ไม่ได้ติดตามผลเบิกจ่ายจริงจาก GFMIS) ขั้น "อนุมัติเบิกจ่าย" นับใบอนุมัติเบิกจ่าย ไม่ใช่เงินที่จ่ายจริง
- ยังไม่ได้ทดสอบบนมือถือ โหมดมืด ปุ่มลัดแป้นพิมพ์ และ screen reader

**ทดสอบ R1 (3 พ.ย. 2569):** build สำเร็จ, 3 หน้าใหม่เปิดได้ไม่มี error/undefined, ผูกเลข e-GP (ผ่านฟังก์ชัน), กันเลขซ้ำ, นำเข้าไฟล์ e-GP และ GF ผ่านปุ่มจริง (แถวที่ไม่พบ Project ID ถูกข้าม, บันทึกในประวัติ), เพิ่มรายการใหม่ในแผนจัดซื้อแล้วได้ Project ID และแถวงบ 1 แถว, บทบาท `plan` นำเข้าไม่ได้ และ `div` เห็นเฉพาะหน่วยตน, แท็บครบลูปแสดงถูก `tests/run.html` โหมด Quick ผ่าน 4,085 รายการ ไม่มีข้อผิดพลาด (ก่อนทำ R1 คือ 4,055) **ยังไม่ได้รัน Full sweep** และยังไม่มีสคริปต์ทดสอบของ R1 ที่เก็บไว้ในโฟลเดอร์ tests (ทดสอบด้วยสคริปต์ครั้งเดียวในเบราว์เซอร์)

## รอบ R4: แผน-ผลเบิกจ่าย เงินกัน เงินพับ (เขียนใหม่ในโปรเจ็คนี้)

ไฟล์ใหม่ `src/js/93-klang-planresult.js` (DATA_V เป็น 41) เมนูอยู่ในแอป Fisko Budget กลุ่ม "แผน-ผลเบิกจ่าย"

| หน้า | ทำอะไร |
|---|---|
| PL1 แผนเบิกจ่าย | ตั้งแผนรายเดือนต่อ Project ID (12 เดือนของปีงบ ไตรมาสและปีรวมให้เอง) เลือกลักษณะงบ งบปีเดียว / ผูกพันใหม่ / ผูกพันเดิม ปรับแผนทุกครั้งเก็บเป็น "ครั้งที่" ใหม่พร้อมเหตุผล ไม่ทับของเดิม แผนรวมเกินวงเงินไม่ได้ |
| PL2 ผลเบิกจ่าย | กรอกผลรายเดือนต่อ Project ID หรือนำเข้าไฟล์ (ที่ PJ3 ชนิด "ผลเบิกจ่ายรายเดือน") ผลสะสมเกินวงเงินไม่ได้ |
| PL3 เงินกัน / เงินพับ | เงินกัน (มีวันขยายเวลา เบิกแล้ว) สถานะอยู่ในเวลา/เบิกครบ/หมดเวลา และเงินพับ ตามนิยามผู้ใช้: เงินกันที่หมดเวลาแล้วคงเหลือเท่าไรเป็นเงินพับ หรืองบที่เบิกไม่ทันสิ้นปีและไม่ได้กัน นำเข้าไฟล์ได้ (ชนิด "เงินกัน / เงินพับ") |
| PL4 แดชบอร์ด | กราฟแผนเทียบผล เลือกรายเดือน/ไตรมาส/ปี เลือกแผนครั้งล่าสุดหรือแผนตั้งต้น KPI แยกตามลักษณะงบและหน่วย |

สิทธิ์ (**สมมุติ ต้องยืนยัน**): `fin`, `finhead` ตั้งแผน ลงผล และจัดการเงินกัน บทบาทอื่นดู หน่วยงานเห็นเฉพาะรายการของตน

**ข้อจำกัดที่รู้:**
- ผลเบิกและเงินกันในระบบจริงมาจาก GF ซึ่งยังไม่เชื่อม ตอนนี้กรอกเองหรือนำเข้าไฟล์รูปแบบสมมุติของเรา
- แผนยังไม่ได้ทำให้ตรงฟิลด์ของ BB-EVACUBE (ยังไม่เห็นรูปแบบจริง) และไม่มีส่งออกไฟล์ให้ BB-EVACUBE
- นิยามเงินพับมาจากผู้ใช้ ยังไม่ได้เทียบกับระเบียบ การคำนวณวันหมดเวลาใช้วันที่ที่กรอกตรง ๆ ไม่มีกฎขยายเวลา
- แผนเบิกตั้งที่ระดับ Project ID รายเดือนของปีงบปัจจุบันปีเดียว ไม่รองรับแผนข้ามปีของงบผูกพัน
- เงินพับรวมในแดชบอร์ดนับทุกปีงบที่มีในทะเบียน ไม่ได้กรองตามปี ยังไม่ได้ทดสอบบนมือถือ โหมดมืด และ screen reader

**ทดสอบ R4 (3 พ.ย. 2569):** build สำเร็จ, 4 หน้าเปิดได้ไม่มี error/undefined, ปรับแผนเกิดครั้งที่ใหม่และเก็บครั้งเดิม, กันแผนเกินวงเงิน กันผลสะสมเกินวงเงิน กันผลซ้ำเดือนเดียวกัน, สถานะเงินกัน (อยู่ในเวลา/หมดเวลา/พับ) ถูกต้อง, นำเข้าไฟล์ผลเบิกและเงินกันผ่านปุ่มจริง (แถวผิดและซ้ำถูกข้าม), `plan` สร้าง/ตั้งแผนไม่ได้ `div` เห็นเฉพาะหน่วยตน, เปลี่ยนมุมมองไตรมาสได้ `tests/run.html` โหมด Quick ผ่าน 4,125 รายการ ไม่มีข้อผิดพลาด **ยังไม่ได้รัน Full sweep** ไม่ได้ทดสอบฟอร์มแก้แผน 12 เดือนผ่านหน้าจอจริง (ทดสอบผ่านฟังก์ชัน)

## รอบ R2: ทะเบียนคุมใบสำคัญเบิกจ่าย (เขียนใหม่ในโปรเจ็คนี้)

ไฟล์ใหม่ `src/js/94-klang-vregister.js` แก้ `vcGroup` ใน `src/js/66c-fin-fn2.js` (DATA_V เป็น 42) เมนูอยู่ในแอป Fisko Finance กลุ่ม "ทะเบียนคุมใบสำคัญ" หน้า PV1

- **ทะเบียนคุม (แทน Google Sheet ที่กองคลังใช้ติดตามการเบิก):** อ่านใบขอเบิกที่มีใน Fisko Finance (F3) แสดงประเภทงาน (ก่อสร้าง / ซื้อจ้างเช่า / ซื้อทั่วไปและค่าใช้จ่ายอื่น) ชนิดงบ (ลงทุน / ดำเนินงาน / เงินนอกงบ) กลุ่มตรวจ 1 หรือ 2 ห้าขั้น (รับพัสดุ, ตรวจเอกสารสำคัญ, เซ็นอนุมัติ, คีย์เบิกของการเงิน, เบิกจ่าย) ใครถืออยู่ ค้างกี่วัน ตารางสรุปจำนวนใบตามประเภทงานและขั้น และส่งออก CSV
- **ข้อมูลที่ทะเบียนเพิ่มเอง:** สำนัก/กองที่ขอเบิก วันที่กองคลังรับเอกสาร หมายเหตุ (กรอกโดย `fin`, `finhead`, `vchk1`, `vchk2` ซึ่งเป็นข้อสมมุติ ต้องยืนยัน)
- **ชนิดงบกับกลุ่มตรวจ:** ใบขอเบิกทุกชนิดที่ตัดจากรายการงบลงทุน เข้ากลุ่ม 2 (เดิมเฉพาะใบที่ผูกสัญญาจัดซื้อ) ชนิดงบอนุมานจากรายการงบของใบ ไม่ได้เพิ่มช่องเก็บในใบขอเบิก

**ที่ไม่ได้ทำใน R2:**
- ยังไม่แยกบทบาทบัญชี / การเงิน / บริหารงบประมาณ ออกจาก `fin` (ต้องรื้อเงื่อนไข `ROLE === "fin"` กว่า 40 จุด เสี่ยงทำของเดิมพัง เสนอแยกเป็นรอบของตัวเองและต้องให้ผู้ใช้ยืนยันกลุ่มงานก่อน)
- ไม่มีขั้น "สำนักกองส่งเอกสาร" ที่ตามจากสำนักกองจริง มีเพียงวันที่รับเอกสารที่กรอกเอง
- ขั้นต่าง ๆ อ่านจากสถานะใบใน Fisko ไม่ใช่ผลจริงจาก GFMIS หรือ KTB เกณฑ์ค้างนาน 7 วันเป็นค่าตัวอย่าง
- ประเภทงานแบ่งจากชนิดแผนจัดซื้อ (ก่อสร้างหรือไม่) ใบที่ไม่ใช่จัดซื้อทั้งหมดเป็น "ซื้อทั่วไปและค่าใช้จ่ายอื่น"
- ยังไม่ได้ทดสอบมือถือ โหมดมืด และ screen reader

**แก้ข้อบกพร่องของ R1 และ R4 ที่พบระหว่างทำ R2:** หน้าใหม่ของ R1 และ R4 เปิดไม่ได้สำหรับบทบาท `vchk1`, `vchk2` และ `hr` เพราะรายชื่อบทบาทถูกอ่านก่อนที่บทบาทเหล่านี้ถูกเพิ่ม แก้โดยใช้ `KROLES` ที่ประกาศใน `92-klang-projid.js` ทดสอบเปิด PJ1, PL4, PV1 ครบทุกบทบาทแล้ว

**ทดสอบ R2 (3 พ.ย. 2569):** build สำเร็จ, หน้า PV1 เปิดได้ไม่มี error ทุกบทบาทที่ลอง (fin, vchk1, vchk2, hr, div, plan), ขั้นและผู้ถือเรื่องของใบตัวอย่าง 9 ใบถูกต้องตามสถานะ, บันทึกสำนักที่ขอเบิกและวันรับเอกสาร (กันวันอนาคต), `plan` แก้ไม่ได้, CSV ส่งออกมีหัวคอลัมน์และข้อมูลไทยถูก (ตรวจข้อความ ไม่ได้เปิดไฟล์ใน Excel), `div` เห็นเฉพาะใบของหน่วยตน `tests/run.html` โหมด Quick ผ่าน 4,135 รายการ ไม่มีข้อผิดพลาด **ยังไม่ได้รัน Full sweep** ยังไม่ได้ทดสอบฟอร์มบันทึกข้อมูลทะเบียนผ่านหน้าจอจริงและปุ่มส่งออก CSV ผ่านการคลิก

## รอบ R3: บริหารสัญญา (เขียนใหม่ในโปรเจ็คนี้ ต่อยอดสัญญาเดิมของ Fisko)

ไฟล์ใหม่ `src/js/95-klang-contracts.js` (DATA_V เป็น 43) เมนูอยู่ในแอป Fisko Contract กลุ่ม "บริหารสัญญา (กองคลัง)" ใช้สัญญา งวด หลักประกัน (หนึ่งฉบับต่อสัญญา) ค่าปรับ ที่ Fisko Procurement/Contract มีอยู่แล้ว ไม่ได้เขียนทับ

| หน้า | ทำอะไร |
|---|---|
| CX1 ทะเบียนสัญญาตาม Project ID | สัญญาทุกฉบับพร้อม Project ID เลข e-GP หลักประกัน ความครบของเอกสาร จำนวนแจ้งเตือน ค้นด้วย Project ID หรือเลข e-GP ได้ มีแท็บเอกสารและแจ้งเตือน |
| CX2 เอกสารประกอบสัญญา | บันทึกว่าแต่ละสัญญามีเอกสารอะไรแล้ว ขาดอะไร จำนวนหน้า สแกน/OCR และเก็บที่ไหน เตือนเอกสารตั้งแต่ 200 หน้าที่ยังไม่ OCR ให้ทยอยส่งเป็นชุด |
| CX3 หลักประกันสัญญา | ทะเบียนหลักประกันทุกสัญญา วันหมดอายุ และบันทึกผลตรวจกับธนาคาร (ยืนยัน/ไม่ตรง/รอผล) ถ้าไม่ตรงแจ้งหัวหน้าพัสดุ |
| CX4 ศูนย์แจ้งเตือน | รวมเรื่องที่ต้องตาม: หลักประกันไม่มี/ใกล้หมด/หมดทั้งที่งวดค้าง, ถึงกำหนดคืนหลักประกัน, งวดเลยกำหนดไม่ตรวจรับ, สัญญาใกล้สิ้นสุด (30 วัน), เอกสารขาด, สัญญาที่ยังไม่ผูกเลข e-GP, ผลตรวจธนาคารไม่ตรง, กรรมการตรวจรับที่ถูกระงับหรือพ้นสภาพ/ไม่อยู่ในทะเบียน HR แบ่งระดับ ต้องทำเดี๋ยวนี้ / เร็ว ๆ นี้ / งานทะเบียน และขึ้นในงานของฉันของพัสดุ |

สิทธิ์ (**สมมุติ ต้องยืนยัน**): `proc`, `prochead` บันทึกเอกสารและผลตรวจธนาคาร บทบาทอื่นดู หน่วยงานเห็นเฉพาะสัญญาของหน่วยตน

**ไม่ได้ทำใน R3:**
- **ร่างสัญญาจากเอกสารที่ได้รับ และตรวจเนื้อหาให้ตรงเอกสารแนบ** ยังไม่ทำ รอตัวอย่างสัญญาจริง
- ไม่ใช่ระบบเก็บเอกสารจริง (Document Center) ไม่ได้เก็บไฟล์ ไม่ได้รัน OCR ตัวอย่างสัญญาหลายร้อยหน้าไม่ได้ทดสอบความเร็ว OCR
- ไม่ได้เชื่อมธนาคาร ผลตรวจพิมพ์เข้าเอง และไม่ได้ทดสอบกับหนังสือค้ำประกันจริง
- หลักประกันยังเป็นหนึ่งฉบับต่อสัญญาตามของเดิม ไม่รองรับหลายฉบับ
- รายการเอกสารที่ต้องมีต่อสัญญา (ตัวสัญญา เอกสารแนบ ราคากลาง คำสั่งกรรมการ หนังสือค้ำ ใบตรวจรับต่องวด) เป็นข้อสมมุติของผม ต้องยืนยันกับระเบียบ
- กรรมการตรวจรับเชื่อม HR เพียงตรวจสถานะ (ระงับ/พ้นสภาพ/ไม่อยู่ในทะเบียน) ไม่ได้ตรวจการโยกย้ายหน่วย
- เกณฑ์ 30 วัน และ 200 หน้า เป็นค่าตัวอย่าง ยังไม่ได้ทดสอบมือถือ โหมดมืด และ screen reader

**ทดสอบ R3 (3 พ.ย. 2569):** build สำเร็จ, 4 หน้าเปิดได้ไม่มี error/undefined ทุกบทบาทที่ลอง (proc, prochead, fin, plan, div, vchk1, hr), สัญญาตัวอย่าง 2 ฉบับแสดงเอกสารขาดและหลักประกันใกล้หมดถูกต้อง, กันเอกสารชนิดซ้ำและใบตรวจรับที่ไม่ระบุงวด, เพิ่มเอกสารแล้วรายการขาดลดลง, บันทึกผลธนาคารไม่ตรงแล้วเกิดแจ้งเตือนระดับ ต้องทำเดี๋ยวนี้, ตั้งหลักประกันหมดอายุ/กรรมการพ้นสภาพ (ในทะเบียน HR) แล้วเกิดแจ้งเตือนและขึ้นในงานของฉัน, แท็บแจ้งเตือนในลิ้นชักแสดงถูก `tests/run.html` โหมด Quick ผ่าน 4,175 รายการ ไม่มีข้อผิดพลาด ฟังก์ชันเพิ่มเอกสารและบันทึกผลธนาคารทดสอบผ่านฟังก์ชัน ไม่ได้ผ่านการกรอกฟอร์มในหน้าจอจริง **ยังไม่ได้รัน Full sweep**

## รอบ R5: งานก่อสร้างสู่สินทรัพย์ และส่งมอบ อปท. (เขียนใหม่ในโปรเจ็คนี้)

ไฟล์ใหม่ `src/js/96-klang-construction.js` (DATA_V เป็น 44) เมนูอยู่ในแอป Fisko Assets กลุ่ม "ก่อสร้างและส่งมอบ (กองคลัง)" ตามหน้าที่ของกลุ่มงานบัญชีข้อ 10-11 (ล้างพักงานระหว่างก่อสร้างขึ้นเป็นสินทรัพย์ และรับ-มอบสินทรัพย์ให้ อปท. โดยตัดออกจาก GF) กับบันทึกประชุม

| หน้า | ทำอะไร |
|---|---|
| CW1 งานก่อสร้างและส่งมอบ | ทะเบียนงานก่อสร้าง 6 ขั้น: ระหว่างก่อสร้าง, แล้วเสร็จ, ล้างพักงานขึ้นเป็นสินทรัพย์ (บันทึกเลขสินทรัพย์จาก GF ประเภทสินทรัพย์ มูลค่า), ส่งมอบให้ อปท. (ชื่อ อปท. วันที่ เลขหนังสือ), อปท.รับมอบ, โอนออกจากระบบ (เลขเอกสารโอนใน GF) ขั้นโอนออกต้องอนุมัติตามขั้น O3 ใหม่ `cwipx` (หัวหน้าการเงิน ถ้าเกิน 50 ล้านบาทเป็นผู้บริหาร ค่าตัวอย่าง) ผู้ขอโอนอนุมัติเองไม่ได้ ผูก Project ID และสัญญาได้ มูลค่าสะสมนับจากใบอนุมัติเบิกจ่ายของสัญญา บวกมูลค่านอกระบบที่กรอก |

ขั้นถัดไปของแต่ละงานบันทึกผ่านปุ่ม "แก้ไข" ในลิ้นชัก (ฟอร์มจะถามข้อมูลของขั้นนั้น) เพราะโครงรายการของ Fisko ให้ปุ่มขั้นถามได้เฉพาะเหตุผล

สิทธิ์ (**สมมุติ ต้องยืนยัน**): `fin`, `finhead` ขึ้นทะเบียนและบันทึกขั้นต่าง ๆ บทบาทอื่นดู หน่วยงานเห็นเฉพาะงานของหน่วยตน

**ไม่ได้ทำใน R5:**
- ไม่ได้บันทึกลง GFMIS เลขสินทรัพย์และเลขเอกสารโอนต้องคีย์ใน GF แล้วนำมากรอกเอง
- ไม่ได้สร้างรายการใน Fisko Assets และไม่คิดค่าเสื่อมของอาคาร/สิ่งก่อสร้างที่ขึ้นเป็นสินทรัพย์

- ยังไม่ได้ตรวจกฎบัญชีว่ามูลค่าที่ขึ้นเป็นสินทรัพย์ต้องเท่ากับมูลค่าสะสม (ผู้ใช้แก้มูลค่าได้ในขั้นล้างพัก)
- ยังไม่ได้ทดสอบมือถือ โหมดมืด และ screen reader

**ข้อบกพร่องที่พบระหว่างทำ:** ชื่อตัวแปร `cwOpen` ซ้ำกับของ Fisko เดิมใน `68-cowork.js` ทำให้ทั้งแอปไม่ขึ้นในรอบ build แรกของ R5 แก้แล้ว และต่อไปตรวจ syntax ของไฟล์ทั้งชุดรวมกันก่อน build (ตรวจรายไฟล์ไม่เจอ)

**ทดสอบ R5 (3 พ.ย. 2569):** build สำเร็จ, 2 หน้าเปิดได้ไม่มี error/undefined ทุกบทบาทที่ลอง (fin, finhead, exec, proc, plan, div, hr, vchk1), เดินงานตัวอย่างครบ 6 ขั้นตามลำดับผ่านฟอร์มแต่ละขั้น, กันเลขสินทรัพย์ซ้ำ และวันที่อนาคต, ผู้ขอโอนออก (fin) อนุมัติเองไม่ได้ หัวหน้าการเงินอนุมัติได้และงานเป็น "โอนออกแล้ว", งานที่โอนออกแล้วแก้ไม่ได้, `plan` ขึ้นทะเบียนหรือแก้ไม่ได้, CW2 แสดงยอดรวมทุกหน่วย `tests/run.html` โหมด Quick ผ่าน 4,195 รายการ ไม่มีข้อผิดพลาด การเดินขั้นทดสอบผ่านฟังก์ชัน ไม่ได้กรอกฟอร์มในหน้าจอจริง และบทบาท `div` ยังไม่มีงานตัวอย่างในหน่วยตนจึงไม่ได้ทดสอบการกรองตามหน่วย **ยังไม่ได้รัน Full sweep**

## รอบ R8: งานการเงินที่ขาด (เขียนใหม่ในโปรเจ็คนี้)

ไฟล์ใหม่ `src/js/97-klang-fin-extra.js` (DATA_V เป็น 45) เมนูอยู่ในแอป Fisko Finance กลุ่ม "งานการเงินอื่นของกองคลัง" 7 หน้า (หน่วยงาน `div`, `divhead` ไม่เห็นกลุ่มนี้ เพราะเป็นงานภายในกองคลัง ซึ่งเป็นข้อสมมุติ)

## รอบ R6: ยานพาหนะ ห้องประชุม อาคารและอุปกรณ์ (เขียนใหม่ในโปรเจ็คนี้)

2. **รายละเอียดเพิ่มตามภาพ** แผงใหม่ในแท็บหลัก ได้แก่ สถานะรายการ (ปีเดียว/ผูกพัน อ่านจากคำขอ เปลี่ยนที่แท็บผูกพันหลายปีเหมือนเดิม), ประเภทงบรายจ่าย (อ่านจากรายการงบประมาณ รหัส 01 ถึง 05 ตามตารางเดิมของระบบ), หมวดรายจ่ายหลัก/ย่อย (**พิมพ์รหัสและชื่อเอง** เพราะผมยังไม่เคยเห็นตารางรหัสจริง), ประจำ/ลงทุน, ประเภทบัญชี 1 ถึง 3, tag รายการ (tag อัตโนมัติ "ที่ดิน/สิ่งก่อสร้างตั้งแต่ 10 ล้านบาท" ตัวเลข 10 ล้านบาทมาจากภาพ แต่เงื่อนไขที่ผมใช้ คือรายการงบลงทุนที่ชื่อเป็นงานก่อสร้างรวมตั้งแต่ 10 ล้านบาท เป็นการตีความของผม), ประเภทเงิน (Entitlement, Obligation, รายจ่ายผูกพัน, Baseline พร้อมภารกิจหน่วยรับงบ/รายจ่ายรักษางานเดิม), เงินนอกสมทบรายการ, แหล่งที่มาของความต้องการ (**รายการให้เลือกเป็นตัวอย่างของผม** ไม่ใช่ตารางของสำนักงบประมาณ) และเพิ่มข้อตรวจ "ข้อมูลตามแบบคำของบ" ในรายการตรวจความครบถ้วน (เตือนอย่างเดียว ไม่บล็อกการส่ง) ขั้น "แผนการใช้จ่าย" และ "สถานะการดำเนินงาน" ตามภาพ มีอยู่แล้วเป็นแท็บแผนรายไตรมาสและความพร้อมของฟอร์มเดิม จึงไม่ทำซ้ำ
3. **สถานะงบหลังเห็นชอบ และยอดที่ได้รับอนุมัติ** คำขอที่ผู้บริหารเห็นชอบแล้วมีขั้น รอส่งสำนักงบประมาณ, ส่งแล้วรอผล, ได้รับอนุมัติงบแล้วรอจัดสรร, นำไปจัดสรรแล้ว (คำนวณจากข้อมูลเดิม ไม่เปลี่ยนสถานะเดิม จึงไม่กระทบหน้าอื่น) ในฟอร์มมีแผง "ผลการพิจารณางบและการจัดสรร" ให้ plan หรือ fin/finhead (**ข้อสมมุติเรื่องสิทธิ์ ต้องยืนยัน**) บันทึกยอดที่ได้รับอนุมัติ (ห้ามเกินยอดที่ขอ ห้ามวันที่อนาคต) ซึ่งเขียนลงที่เดียวกับหน้าส่งสำนักงบประมาณ (M05) และหน้าจัดสรร (M06) แล้วกด "นำรายการไปจัดสรร" (fin, finhead) เพิ่มบรรทัดในร่างการจัดสรรปีที่กำลังจัดทำ แก้ยอดทีหลังบรรทัดจัดสรรที่เป็นร่างปรับตาม รายการคำขอมีคอลัมน์ "สถานะงบ / จัดสรร" และตัวกรอง
4. **เลือกปีงบประมาณด้านบน** ที่หน้ารายการคำขอ แสดงปีจาก fyList (2569 ถึง 2572) ปีที่กำลังจัดทำ (2571) แสดงรายการคำขอตามเดิม ปีอื่นแสดงเฉพาะ **บรรทัดจัดสรรของปีนั้น (อ่านอย่างเดียว)** เพราะต้นแบบเก็บคำขอเดิมไว้เฉพาะปีที่กำลังจัดทำ ข้อมูลตัวอย่างมีการจัดสรรเฉพาะปี 2570 ปี 2569 และ 2572 จะแสดงว่าไม่มีข้อมูล
5. **ตัวเลือกปีงบประมาณทั้งระบบ** ที่แถบด้านบน (ไฟล์ `src/js/98w-klang-fiscalyear.js` จำค่าไว้ในเบราว์เซอร์) ค่าเริ่มต้น "ตามหน้า" = ทุกหน้าเหมือนเดิม เมื่อเลือกปี หน้าที่มีข้อมูลปีนั้นแสดงตามปกติ หน้าที่ต้นแบบไม่มีข้อมูลปีนั้นจะแสดง **ข้อความแจ้ง** พร้อมปุ่มไปดูปีที่หน้านั้นมีข้อมูล หรือล้างตัวเลือก (ไม่แสดงตัวเลขปีอื่นใต้ป้ายปีที่เลือก) ปีที่ต้นแบบมีข้อมูล: ปีที่กำลังจัดทำ 2571 (คำขอ รวมคำขอ พิจารณา ส่ง สงป.) ปีใช้จ่าย 2570 (หน้าอื่นเกือบทั้งหมด) และบรรทัดจัดสรรที่หน้าจัดสรรกับรายการคำขอ หน้าที่ไม่ขึ้นกับปี (หน้าหลัก ผู้ดูแล คู่มือสาธิต ผู้ช่วย AI Flow) ไม่ถูกแทน ทดสอบด้วย `tests/klang.js` กลุ่ม "Fiscal-year selector" และ Full sweep ผ่านโดยตั้งค่าปีเป็น "ตามหน้า"

6. **ฟอร์มสร้างคำขอใหม่ (4 พ.ย. 2569)** ช่องกิจกรรมตอนนี้เลือกเป็นสองขั้น: **ผลผลิต/โครงการ** ก่อน แล้วรายการ **กิจกรรม** จะแสดงเฉพาะที่อยู่ใต้ผลผลิต/โครงการนั้น (แผนงานที่ไม่มีผลผลิตใช้แทนผลผลิตได้ เช่น แผนงานบุคลากร) ฟอร์มแก้ไขข้อมูลหลักในลิ้นชักใช้แบบเดียวกัน (`rqOutAct` ใน `78-form-crud.js`)
7. **กิจกรรมกับ "กิจกรรมตามโครงสร้างงบประมาณ" เป็นรายการเดียวกัน** (ค่า `act` ของคำขอ จากโครงสร้างงบประมาณชุดเดียวกัน) จึงตัดช่องเลือกที่ซ้ำในหน้าคำขอออก เหลือช่องเดียวในแผง "ข้อมูลโครงการและการจัดประเภทคำขอ" และคงข้อความตัวชี้วัดของกิจกรรมไว้ ส่วนหน้าจัดสรรและหน้าโครงสร้างงบประมาณของผู้ดูแลระบบยังมีช่องกิจกรรมของตัวเอง เพราะเป็นคนละฟอร์ม
8. **ทะเบียนผลผลิต/โครงการ (RG1) และทะเบียนกิจกรรม (RG2)** ในแอป Fisko Budget กลุ่ม "ทะเบียนโครงสร้างงบประมาณ" (`98v-klang-registers.js`) เป็นข้อมูลชุดเดียวกับโครงสร้างงบประมาณที่ฟอร์มคำขออ่าน จึงเพิ่มในทะเบียนแล้วขึ้นในฟอร์มทันที ทำได้: เพิ่ม แก้รหัส/ชื่อ เลิกใช้ (เมื่อมีคำขอ จัดสรร ตัวชี้วัด หรือรายการลูกอ้างถึง) ลบ (เมื่อยังไม่มีผู้ใช้) ไม่ให้รหัสซ้ำ ปีที่ปิดแล้วอ่านอย่างเดียว ผู้เพิ่ม/แก้ได้คือผู้ดูแลระบบและฝ่ายแผน (**ข้อสมมติของผม ต้องยืนยัน**) บทบาทหน่วยงานไม่เห็นหน้านี้ ไม่ได้ดึงรหัสจากระบบภายนอก
9. **ตัวเลือกปีงบประมาณแสดงเฉพาะหน้างบประมาณ** (ปรับจากข้อ 5): แสดงและใช้เฉพาะหน้าในแอป Fisko Budget ที่ขึ้นกับปี หน้าของแอปอื่น (จัดซื้อ การเงิน สัญญา ทรัพย์สิน บุคลากร ฯลฯ) และหน้าหลัก/ผู้ดูแล/AI ไม่แสดงตัวเลือกและไม่ถูกแทนด้วยข้อความแจ้ง ทดสอบใน `tests/klang.js` (862 รายการ) และ Full sweep (15,875 รายการ) ผ่าน

10. **สถานะรายการในแผนจัดซื้อชัดขึ้น (4 พ.ย. 2569)** รายการที่ยังไม่อยู่ในแผนฉบับที่ประกาศ แสดงสถานะ **"ร่างในแผน"** (แทน "อยู่ในแผน") และป้ายใต้ชื่อบอกขั้นจริง: ยังไม่ได้เสนอแผน / รอผู้บริหารอนุมัติแผน / อนุมัติแล้ว รอบันทึกประกาศใน e-GP / แผนฉบับล่าสุดไม่อนุมัติ ปรับแล้วเสนอใหม่ เมื่อบันทึกเลขที่ประกาศแล้วเป็น "อยู่ในแผน" รายการที่ขอซื้อหรือทำสัญญาแล้วคงสถานะเดิม (`planStage`, `planStat` ใน `61c-planreports.js`) ทดสอบทุกขั้นใน `tests/klang.js` และเดินจริงในหน้าจอ (พัสดุเพิ่มรายการ → เสนอแผน → ผู้บริหารอนุมัติ → พัสดุบันทึกประกาศ) ข้อสังเกต: Project ID ออกตั้งแต่เพิ่มรายการ ถ้าแผนไม่อนุมัติรหัสยังอยู่ ยังไม่มีการยกเลิกรหัส

**ไม่ได้ทำ/ข้อจำกัด:** ไม่ได้ส่งหรือรับข้อมูลกับสำนักงบประมาณจริง ไม่มีตารางรหัสหมวดรายจ่ายจริง ไม่ได้ตรวจหน้าตาด้วยตา (ทดสอบด้วยสคริปต์และการคลิกฟอร์มจริงบางส่วน) ไม่ได้ทดสอบมือถือ โหมดมืด กรอกฟอร์มด้วยแป้นพิมพ์จริง การเพิ่มบรรทัดจัดสรรทำได้เฉพาะเมื่อการจัดสรรปีนั้นยังเป็นร่าง (ถ้าจัดสรรตาม พ.ร.บ. แล้วให้ไปที่หน้าจัดสรร) ฟิลด์ใหม่ยังไม่ปรากฏในหน้าจัดสรร แผนจัดซื้อ หรือรายงานอื่น ตัวเลือกปีทั้งระบบไม่ได้ทำให้ทุกหน้ามีข้อมูลทุกปี (ต้นแบบมีข้อมูลตัวอย่างเพียง 2570 และ 2571) และยังไม่ได้ตรวจหน้าตาด้วยตา

**ทดสอบ (4 พ.ย. 2569):** Full sweep ผ่าน 15,763 รายการ ไม่มีข้อผิดพลาด (115 วินาที) `tests/klang.html` ผ่าน 782 รายการ (เพิ่มกลุ่มทดสอบคำขอหลัก) เลือกแผนงาน/ผลผลิต/กิจกรรมผ่านช่องเลือกจริง, ติ๊ก/กรอกฟิลด์ใหม่ได้และบันทึก, บันทึกยอดอนุมัติเกินยอดขอถูกปฏิเสธ, บันทึกยอดที่ถูกต้องแล้วสถานะเป็น "ได้รับอนุมัติงบ", นำไปจัดสรรแล้วเกิดบรรทัด N1 ยอด 5.5 ล้านบาท และแก้ยอดแล้วบรรทัดปรับตาม, หน้าจัดสรรเปิดได้, บทบาท div ไม่เห็นช่องบันทึกยอด, สลับปีด้านบนได้ครบ 4 ปี

## รอบ P1: คณะกรรมการในการจัดซื้อจัดจ้าง (ทำ 9 พ.ย. 2569 ออกแบบใหม่ 10 พ.ย. 2569) ส่วนหนึ่งของการปรับ flow จัดซื้อ

ไฟล์ `src/js/98zb-klang-committee.js` แก้เพิ่มใน `61-cases.js` (ส่วนคณะกรรมการของแฟ้มจัดซื้อ), `60-procurement.js` และ `63-contracts.js` (สร้างสัญญา เปลี่ยนกรรมการ ข้อความลงนาม) `DATA_V` เป็น 53 **ออกแบบรอบแรก (ทะเบียนลอย ผูกสัญญา) ผิดทิศ แก้เป็นแบบนี้ตามคำสั่งผู้ใช้ 10 พ.ย.**

- **ประเภทคณะกรรมการ (ส่วนกลาง CM4)** หัวหน้าพัสดุและผู้ดูแลระบบแก้ได้ ใช้ร่วมกันทุกหน่วย แต่ละประเภทกำหนด: ชื่อ, รายละเอียด, ใช้เป็นแบบใด (TOR, พิจารณาผล, ซื้อหรือจ้าง, ตรวจรับ, อื่น ๆ), งานก่อสร้างต้องมีผู้มีความรู้ด้านช่างหรือไม่, และ **ห้ามสมาชิกซ้ำกับประเภทไหนในการจัดซื้อเดียวกัน** (ตั้งข้างใดข้างหนึ่งก็ใช้ทั้งสองทาง)
- **ตำแหน่งสมาชิกของประเภท (CM6)** เช่น ประธาน (1 คน), กรรมการ, ผู้ทรงคุณวุฒิ/ช่าง กำหนดจำนวนต่ำสุด สูงสุด (ว่าง = ไม่จำกัด) ใครดำรงได้ (ผู้ใช้ในระบบ คนนอก หรือทั้งคู่) และตำแหน่งไหนเป็นประธาน จำนวนจริงในช่วงนี้ **เจ้าหน้าที่เลือกหรือตามมติที่ประชุม**
- **ใช้ในการจัดซื้อ:** หน้าแฟ้มจัดซื้อ ส่วน "คณะกรรมการ" แสดงทุกประเภทที่แฟ้มต้องใช้ (ตามวิธีจัดหา และคณะตรวจรับ) และเพิ่มประเภทอื่นได้ แต่ละประเภทตั้งคณะ (เลขที่คำสั่ง วันที่ ชื่อไฟล์) แล้วใส่สมาชิกตามตำแหน่ง ผู้ใช้ในระบบหรือคนนอก (ชื่อ หน่วยงาน ตำแหน่ง) ระบบกันคนซ้ำข้ามคณะที่ประเภทห้ามไว้ และกันตำแหน่งเต็ม แฟ้มจะไปขั้นต่อไปได้เมื่อคณะครบเงื่อนไข **เจ้าหน้าที่พัสดุ และสำนัก/กองเจ้าของเรื่อง ใส่หรือแก้สมาชิกได้ รวมถึงหลังประชุม** จนกว่าจะมีการลงนามตรวจรับ
- **ทะเบียน (CM1 คณะ, CM2 สมาชิก)** เป็นรายการรวมของทุกแฟ้ม แก้ได้เหมือนในหน้าแฟ้ม **CM3** บันทึกการเข้าประชุม: กรรมการที่ไม่เข้าให้คนอื่นเข้าแทนได้ ต้องระบุชื่อ หน่วยงาน ตำแหน่ง และหนังสือมอบหมาย (เลขที่ ลงวันที่ ชื่อไฟล์)
- **ตรวจรับ/สัญญา:** ฟอร์มสร้างสัญญาและ "เปลี่ยนกรรมการ" เลือกคณะตรวจรับของแฟ้มนั้น คณะที่ไม่ผ่านเงื่อนไขเลือกไม่ได้และบอกเหตุผล วงเงินไม่เกินเกณฑ์ตรวจรับคนเดียว (M10) ลดเงื่อนไขขั้นต่ำเหลือ 1 คน กรรมการคนนอกลงนามในระบบไม่ได้ เจ้าหน้าที่พัสดุ "บันทึกผลตรวจรับแทน" ระบุวันที่ลงนามบนกระดาษ เลขที่เอกสาร ชื่อไฟล์ และผู้แทนพร้อมหนังสือมอบหมาย (ถ้ามี) นับเป็นลายมือชื่อครบองค์ประชุม และข้อความลงนามแสดง "บันทึกแทน"
- **ข้อมูลเดิม:** คณะ TOR/พิจารณาผล/ซื้อหรือจ้างของแฟ้มตัวอย่าง และรายชื่อตรวจรับของสัญญาตัวอย่าง ถูกแปลงเข้าทะเบียนอัตโนมัติ (ประธานเข้าตำแหน่งประธาน คนอื่นเข้าตำแหน่งกรรมการ) ส่วนที่แฟ้มอื่นเขียนคณะขึ้นเอง (เช่นตัวช่วย AI) จะถูกนำเข้าทะเบียนเมื่อเปิดหน้า `c.committees` ในแฟ้มยังเป็นสำเนาของทะเบียน (เฉพาะสมาชิกที่เป็นผู้ใช้) เพื่อให้การแจ้งผลประโยชน์ทับซ้อน การให้คะแนน และรายงานค่าตอบแทนที่อ่านค่านี้ทำงานต่อ
- **ข้อจำกัดที่ต้องรู้:** เก็บ **ชื่อไฟล์** ของคำสั่งและหนังสือเท่านั้น ไม่เก็บไฟล์จริง จำนวนคน ตำแหน่ง และกติกาซ้ำซ้อนในข้อมูลตัวอย่างเป็น **ค่าตัวอย่างที่ผมตั้งเอง ไม่ได้อ้างมาตราของกฎหมาย** ต้องให้ผู้รู้ระเบียบยืนยัน กรรมการคนนอกไม่มีบัญชี จึงไม่มีการแจ้งผลประโยชน์ทับซ้อนหรือให้คะแนนในระบบ (ระบบนั้นทำเฉพาะผู้ใช้) ยังไม่ผูกกับขั้นตอนใหม่ของ P2 ขึ้นไป ยังคงเกณฑ์ลงนามครบ 2 ลายมือชื่อเดิม (`PHASE_SIGNS`) ไม่ว่าคณะจะมีกี่คน การที่สำนัก/กองเจ้าของเรื่องแก้ได้ขึ้นกับว่าผู้ใช้อยู่หน่วยเดียวกับเจ้าของรายการ
- **ทดสอบ (10 พ.ย. 2569):** `tests/klang.html` ผ่าน 1,017 รายการ (กลุ่ม "Committee types and case committees (P1)": โครงสร้างตำแหน่ง ขั้นต่ำ/สูงสุด ซ้ำข้ามคณะสองทิศทาง งานก่อสร้างต้องมีช่าง SD-02 ชนิดผู้ดำรงตำแหน่ง สำเนา `c.committees` สิทธิ์แก้ประเภท ตั้งคณะและเพิ่ม/นำสมาชิกออกผ่านฟอร์มจริงบนหน้าแฟ้ม บันทึกแทนคนนอกและผู้แทน ล็อกสมาชิกหลังลงนามตรวจรับ หน้าใหม่ 6 หน้า × ทุกบทบาท) Full sweep ผ่าน 16,619 รายการ ไม่มีข้อผิดพลาด ยังไม่ได้ตรวจหน้าตาด้วยตา

### ปรับเงื่อนไขคณะกรรมการตามระเบียบที่ผู้ใช้ให้มา (10 พ.ย. 2569)

ผู้ใช้ส่งข้อความสรุประเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560 ให้ตั้งเงื่อนไข ผมนำไปใส่ตามที่ให้มา **ไม่ได้ตรวจกับตัวระเบียบเอง** (ข้อความที่ให้มา ผมไม่ได้เทียบกับต้นฉบับ) จึงยังเป็นเงื่อนไขที่ต้องให้ผู้รู้ระเบียบยืนยัน

- **ประเภทที่ตั้งไว้ 7 ประเภท:** จัดทำ TOR (ของขั้นตอนใหม่) + 6 คณะตามที่ให้มา คือ พิจารณาผลประกวดราคาอิเล็กทรอนิกส์, พิจารณาผลการสอบราคา, ซื้อหรือจ้างโดยวิธีคัดเลือก, ซื้อหรือจ้างโดยวิธีเฉพาะเจาะจง, ตรวจรับพัสดุ, กำหนดราคากลาง ทุกประเภทมีประธาน 1 คน และกรรมการอย่างน้อย 2 คน (รวมไม่น้อยกว่า 3) บุคคลภายนอกได้ไม่เกิน 2 คน (ตั้งต่อประเภทได้) คณะตรวจรับมีตำแหน่งผู้ทรงคุณวุฒิ/ช่างเพิ่มได้ 0 ถึง 2 คน
- **ผู้ตรวจรับพัสดุ 1 คน:** ถ้าวิธีเฉพาะเจาะจงและวงเงินไม่เกินเพดานวิธีเฉพาะเจาะจง (M10 ค่าตั้งต้น 500,000 บาท) ใช้ผู้ตรวจรับ 1 คนแทนคณะได้ เกณฑ์ลงนามตรวจรับของงวดจะเหลือ 1 ลายมือชื่อ (`ph.need`) กรณีอื่นยัง 2 ลายมือชื่อเหมือนเดิม
- **กฎซ้ำซ้อน เปลี่ยนจาก "ห้ามซ้ำ" เป็นกฎต่อคู่ประเภท** ตั้งที่ CM4 ต่อประเภทอื่นได้ 2 อย่างพร้อมกัน: โหมด (ไม่จำกัด / ห้ามซ้ำทุกคน / ห้ามประธานของคณะนี้ซ้ำ) และเพดานร้อยละที่ซ้ำได้ของคณะนี้ ตามที่ให้มา คณะตรวจรับ: ประธานต้องไม่เป็นประธานหรือกรรมการของคณะพิจารณาผล/ซื้อหรือจ้าง (คัดเลือก เฉพาะเจาะจง สอบราคา) ในงานเดียวกัน ส่วนกรรมการตรวจรับเป็นกรรมการพิจารณาผลได้ไม่เกินร้อยละ 50 ระบบตรวจทั้งฝั่งตรวจรับและฝั่งพิจารณาผล (เพิ่มสมาชิกฝั่งใดแล้วทำให้ผิดกฎ จะถูกปฏิเสธพร้อมเหตุผล)
- **ที่ยังไม่ได้ทำตามข้อความที่ให้มา:** ตรวจว่าสมาชิกเป็นข้าราชการ ลูกจ้างประจำ พนักงานราชการ หรือพนักงานของหน่วยงาน (ระบบถือว่าผู้ใช้ในระบบเป็นบุคลากรของหน่วยงานอยู่แล้ว ไม่มีช่องประเภทบุคลากร) ผู้แทนชุมชน/ผู้ใช้บริการ ใช้ช่องบุคคลภายนอกเดียวกัน คณะสอบราคากับกำหนดราคากลางยังไม่ผูกกับวิธีจัดหาในค่าตั้งวิธี (M10 ซึ่งไม่มีวิธีสอบราคา) แฟ้มจัดซื้อแสดง "เพิ่มคณะกรรมการประเภทอื่น" ให้เลือกเอง คณะราคากลางแสดงเสมอ และคณะเฉพาะเจาะจงแสดงเมื่อวิธีเป็นเฉพาะเจาะจง สอบราคาไม่ได้ถูกผูกกับขั้นตอนใดของแฟ้ม (ไม่มี COI คะแนน หรือรายงานค่าตอบแทนของคณะที่ไม่ใช่ TOR พิจารณาผล ซื้อหรือจ้างคัดเลือก)
- **ข้อควรให้ผู้รู้ตรวจ:** วิธี "สอบราคา" ในข้อความที่ให้มา ผมจำได้ว่าระเบียบฉบับ พ.ศ. 2560 ใช้วิธีอื่น ผมไม่แน่ใจ จึงตั้งเป็นประเภทที่เลือกเพิ่มได้ ไม่ผูกกับวิธีใด และทำคำอธิบายในประเภทว่า "ต้องให้ผู้รู้ระเบียบยืนยัน"
- **ทดสอบหลังปรับเงื่อนไข (10 พ.ย. 2569):** `tests/klang.html` ผ่าน 1,023 รายการ (เพิ่มข้อสอบกฎกรรมการ: ประธานซ้ำ ซ้ำเกินครึ่ง มองจากฝั่งพิจารณาผล ผู้ตรวจรับ 1 คน ลงนาม 1 ลายมือชื่อ คนนอกเกินกำหนด) Full sweep ผ่าน 16,619 รายการ ไม่มีข้อผิดพลาด

### เอกสารแนบของคณะกรรมการ (10 พ.ย. 2569)

ทุกคณะกรรมการแนบเอกสารที่เกี่ยวข้องได้ และแนบได้ทุกจังหวะที่เพิ่มคณะ (`98zb-klang-committee.js`, `DATA_V` เป็น 54)

- **ชนิดเอกสาร:** คำสั่งแต่งตั้ง, รายงานการประชุม/มติ, หนังสือมอบหมาย/หนังสือแจ้ง, แบบแจ้ง/คุณสมบัติ, เอกสารอื่น พร้อมหมายเหตุ เก็บชื่อ ขนาด ชนิดไฟล์ วันเวลา และผู้แนบ
- **ทุกจังหวะที่เพิ่มคณะ:** (1) ฟอร์ม "ตั้งคณะกรรมการ" ในแฟ้มจัดซื้อ (2) "เพิ่มคณะกรรมการประเภทอื่น" ในแฟ้ม (3) ฟอร์ม "เพิ่มคณะกรรมการ" ที่ทะเบียน CM1 ทั้งสามจุด **ต้องแนบไฟล์คำสั่งแต่งตั้ง** และแนบเอกสารอื่นหลายไฟล์ได้ ไฟล์คำสั่งแรกเป็นชื่อที่ใช้ตรวจเงื่อนไข "มีเลขที่ วันที่ ไฟล์คำสั่ง"
- **แนบเพิ่มภายหลังได้ตลอด** ในแฟ้มจัดซื้อ (ใต้ตารางตำแหน่ง) และที่ CM1 แท็บ "เอกสารแนบ" ลบได้ ยกเว้นไฟล์คำสั่งสุดท้ายที่ลบไม่ได้ สิทธิ์เดียวกับการแก้คณะ (พัสดุ และสำนัก/กองเจ้าของเรื่อง) แนบเอกสารได้แม้หลังมีการลงนามตรวจรับ (ล็อกเฉพาะสมาชิก) ตาราง CM1 มีคอลัมน์จำนวนเอกสาร
- **ข้อจำกัด:** ต้นแบบเก็บข้อมูลในเบราว์เซอร์ ไฟล์ไม่เกิน 200 KB เก็บเนื้อหาไว้ด้วย (กดชื่อเพื่อเปิด/ดาวน์โหลดได้) ไฟล์ใหญ่กว่านั้นเก็บเฉพาะชื่อและขนาด ไม่มีที่เก็บไฟล์จริง ไม่ตรวจชนิดไฟล์หรือไวรัส ข้อมูลตัวอย่างมีเฉพาะชื่อไฟล์ ("ไม่มีไฟล์จริง") **หนังสือมอบหมายผู้แทนในหน้า CM3 และฟอร์มบันทึกลงนามแทนยังเป็นช่องชื่อไฟล์** (ยังไม่ได้เปลี่ยนเป็นแนบไฟล์จริง) ใช้แนบหนังสือไว้ที่แท็บเอกสารแนบของคณะแทนได้
- **ทดสอบ (10 พ.ย. 2569):** `tests/klang.html` ผ่าน 1,033 รายการ (ตั้งคณะโดยไม่แนบไฟล์คำสั่งถูกปฏิเสธ, แนบไฟล์คำสั่งและเอกสารอื่นผ่านฟอร์มจริงด้วยไฟล์ที่เลือก, แนบเพิ่มภายหลัง, ลบ, ลบไฟล์คำสั่งสุดท้ายไม่ได้, ฟอร์มทะเบียน) Full sweep ผ่าน 16,619 รายการ ไม่มีข้อผิดพลาด ยังไม่ได้ทดสอบด้วยเลือกไฟล์จริงจากกล่องเลือกไฟล์ของเบราว์เซอร์ (ทดสอบด้วยการกำหนดไฟล์ในสคริปต์)

### เอาหน้า "เงื่อนไขทั่วไปของคณะกรรมการ" (CM5) ออก (10 พ.ย. 2569)

หน้านี้มีสวิตช์ 2 ข้อ ซึ่งซ้ำกับของที่มีอยู่แล้ว จึงเอาออก: (1) "ต้องมีเลขที่ วันที่ ไฟล์คำสั่ง" ตอนนี้ทุกจุดที่เพิ่มคณะบังคับแนบไฟล์คำสั่งอยู่แล้ว จึงเป็นเงื่อนไขตายตัว ปิดไม่ได้ (2) "ห้ามเจ้าหน้าที่พัสดุเป็นกรรมการ" ซ้ำกับกฎแยกหน้าที่ SD-02 ของผู้ดูแลระบบ ตอนนี้ระบบตรวจตามกฎ SD-02 นั้นโดยตรง ปิดกฎที่หน้าการแยกหน้าที่ของผู้ดูแลระบบได้ ไม่มีข้อมูลหรือพฤติกรรมอื่นเปลี่ยน เมนูกลุ่ม "คณะกรรมการ" เหลือ CM1, CM2, CM3, CM4, CM6 (เลขหน้าไม่เรียงใหม่) `tests/klang.html` ผ่าน 1,016 รายการ (ลดจากหน้าที่เอาออก)

- **วิธีทำ:** หน้าแฟ้มยังสร้างจาก `caseDetail` และ `CASE_PANELS` ของไฟล์อื่น แล้วย้ายแผงเข้าแผงหลักตามหัวข้อหลังวาด (ตัวจัดการปุ่มยังอยู่กับแผงที่ย้าย) หัวข้อที่ไม่รู้จัก (แผงใหม่ที่ไฟล์อื่นเพิ่มภายหลัง) จะไปอยู่ในส่วนพับของแผงจัดทำข้อมูล
- **ยังไม่ได้ทำ (รอบ B):** ฟอร์มขอจัดซื้อในหน้าแฟ้มแทน pop-up, ให้สำนัก/กองเลือกวิธีจัดหา, ให้ผู้มีอำนาจของสำนัก/กอง (หัวหน้า ผู้บริหาร หรือผู้มีสิทธิ์อนุมัติ) อนุมัติวิธีและใบขอซื้อ ตอนนี้ยังเป็นพัสดุเลือกวิธี หัวหน้าพัสดุอนุมัติ และ pop-up เดิม

## รอบ B: ขอจัดซื้อในหน้าแฟ้ม วิธีจัดหาโดยสำนัก/กอง อนุมัติโดยผู้มีอำนาจของสำนัก/กอง (12 พ.ย. 2569)

ไฟล์ใหม่ `src/js/98ze-klang-requisition.js` แก้ใน `60-procurement.js` (เอา pop-up `rq-dlg` และตัวจัดการปุ่มส่งเดิมออก) `61-cases.js` (แผงวิธีจัดซื้อ ราคากลาง TOR คณะกรรมการ เห็นตั้งแต่ขั้นแรก) `98zc` `98zd`

- **ปุ่ม "ขอซื้อขอจ้าง" ในหน้าแผนจัดซื้อ** เปิดหน้าแฟ้มของรายการนั้นที่แผงหลัก "จัดทำข้อมูล" ไม่มี pop-up แล้ว
- **ในแผง "จัดทำข้อมูล"** แผงย่อย "ขอจัดซื้อ" เป็นฟอร์มเดิม (1 วงเงินและเหตุผล 2 รายละเอียดโครงการ 3 เอกสารแนบ) เพิ่ม 4 "พร้อมส่งหรือยัง" แสดงรายการที่ต้องพร้อม: วิธีจัดหา ราคากลาง TOR (ถ้าวิธีนั้นต้องมี) และคณะกรรมการ TOR ครบเงื่อนไข ปุ่ม "ส่งให้ผู้มีอำนาจอนุมัติ" กดได้เมื่อครบ และมี "บันทึกร่าง" ข้อมูลที่พิมพ์ไว้เก็บเป็นร่างในแฟ้ม (`c.rqDraft`) ไม่หายเมื่อไปใช้แผงอื่นในหน้าเดียวกัน
- **วิธีจัดหา** สำนัก/กองเจ้าของเรื่องเลือกได้ (ก่อนใบขอซื้อได้รับอนุมัติ) เจ้าหน้าที่พัสดุยังแก้ได้เหมือนเดิม ถ้าต่างจากคำแนะนำหรือมีเหตุพิเศษ ต้องมีเหตุผลเหมือนเดิม แต่ **ไม่ส่งให้หัวหน้าพัสดุแล้ว** ผู้มีอำนาจของสำนัก/กองอนุมัติพร้อมใบขอซื้อในครั้งเดียว (สถานะ `with_request` เป็น `approved`)
- **ผู้มีอำนาจอนุมัติ** คือผู้บริหารที่มีสิทธิ์อนุมัติ (`canSpend` รวมผู้รับมอบอำนาจ) หรือหัวหน้าสำนัก/กอง (บทบาท divhead) ของหน่วยที่เป็นเจ้าของรายการ ผู้ขอและเจ้าหน้าที่พัสดุอนุมัติไม่ได้ ปุ่มอนุมัติ/ไม่อนุมัติอยู่ในแผงเดียวกัน และที่หน้า "ใบขอซื้อขอจ้าง" เดิมด้วย แจ้งเตือนไปที่ divhead และผู้บริหาร
- **หลังอนุมัติ** (ขั้นที่ 3) สำนัก/กองกด "ส่งให้กองคลัง" เจ้าหน้าที่พัสดุกด "รับเรื่อง" แล้วแฟ้มเลื่อนไปขั้นที่ 4 เอง (ไม่ต้องกด "ไปขั้นจัดทำ TOR" อีก)
- **TOR แนบเป็นเอกสาร** แผง TOR แนบไฟล์ได้หลายไฟล์ (ร่างหรือฉบับสมบูรณ์) พร้อมหมายเหตุ ไฟล์ไม่เกิน 200 KB เก็บเนื้อหา (กดชื่อเปิด/ดาวน์โหลดได้) ใหญ่กว่านั้นเก็บชื่อ ลบไฟล์ได้ ยังเลือกใช้แม่แบบ TOR เดิมได้
- **ข้อจำกัด:** ผู้บริหารของหน่วยอื่นที่ได้รับมอบอำนาจแทนสำนัก/กองนี้ ยังไม่ได้ทำ (มีเฉพาะ divhead ของหน่วยเดียวกันและผู้บริหารที่ `canSpend`) ใบขอซื้อเดิมที่รออนุมัติอยู่ในข้อมูลตัวอย่าง ผู้อนุมัติเปลี่ยนตามกฎใหม่ ไฟล์แนบของใบขอซื้อยังเก็บชื่อ ขนาด ชนิดเท่านั้น (ไม่เก็บเนื้อไฟล์) ชื่อ `rqPanel` ซ้ำกับหน้าคำขอตั้งงบ จึงตั้งชื่อฟังก์ชันของหน้าแฟ้มเป็น `rqCasePanel`

## รอบ Q4b: พื้นที่และพิกัด ทะเบียนราคากลาง แผนรายเดือน (12 พ.ย. 2569)

ไฟล์ใหม่ `src/js/98zf-klang-reqplan.js` แก้เพิ่มเล็กน้อยใน `41c-req-depth.js` (ตัวหาราคามาตรฐานเปลี่ยนเป็น `let` เพื่อให้เลิกใช้ราคาที่เลิกใช้/หมดอายุ) `DATA_V` เป็น 58 ไม่แตะไฟล์จัดซื้อ

- **พื้นที่ดำเนินงาน (หน้าหลักของคำขอ):** ระบุได้หลายแห่ง แต่ละแห่ง จังหวัด อำเภอ ตำบล และละติจูด/ลองจิจูด พิมพ์หรือเลือกจากรายการ ถ้าชื่อตรงกับตารางพื้นที่ (หน้า **BQ4** กองแผนงานดูแล) ระบบใส่พิกัดให้ ถ้าไม่ตรงพิมพ์พิกัดเอง ระบบเตือนเมื่อพิกัดอยู่นอกประเทศไทย (ช่วงโดยประมาณ) งบลงทุนที่ไม่ระบุพื้นที่ขึ้นเตือนในรายการตรวจ **ตารางเริ่มต้น 10 แถวเป็นตัวอย่างของผม พิกัดโดยประมาณ ไม่ใช่ข้อมูลทางการ** และต้นแบบไม่ได้ค้นพิกัดจากแหล่งภายนอก
- **ทะเบียนราคากลาง (หน้า BQ5):** เป็นบัญชีราคามาตรฐานชุดเดิม (ที่กฎ BR-05 ใช้เตือนราคาสูงกว่า) เพิ่มแหล่งที่มา (บัญชีราคามาตรฐาน, e-GP, ใบเสนอราคา, ราคาในสัญญาเดิม, อื่น ๆ) วันที่ใช้ได้ตั้งแต่/ถึง และเอกสารอ้างอิง กองแผนงาน กองคลัง และผู้ดูแลระบบแก้ได้ ราคาที่เลิกใช้ หมดอายุ หรือยังไม่ถึงวันใช้ จะไม่ถูกใช้ในรายการงบประมาณของคำขอ ลบได้เมื่อไม่มีรายการอ้างถึง ไม่เช่นนั้นเลิกใช้
- **แผนรายเดือน (แท็บแผนของคำขอ ต่อจากแผนรายไตรมาส):** 12 เดือน (ต.ค. ถึง ก.ย.) แผนใช้จ่าย สถานะดำเนินงานรายเดือน (ยังไม่เริ่ม กำลังดำเนินการ แล้วเสร็จ ล่าช้า) และผลรายเดือน มียอดสะสมและร้อยละผลต่อยอดอ้างอิง ปุ่มกระจายตามแผนรายไตรมาส กระจายเท่ากัน ปรับให้เท่ายอด ล้างแผน ยอดอ้างอิงคือยอดที่ขอ และเปลี่ยนเป็นยอดที่ได้รับอนุมัติเมื่อบันทึกแล้ว เตือนเมื่อแผนรวมไม่เท่ายอด และเมื่อรายไตรมาสไม่ตรงแผนรายไตรมาส
- **สิทธิ์ (ข้อสมมุติของผม ต้องยืนยัน):** สำนัก/กองแก้แผนรายเดือนของคำขอตนเองตอนเป็นร่างหรือถูกส่งกลับ หลังบันทึกยอดที่ได้รับอนุมัติ สำนัก/กองเจ้าของคำขอและกองแผนงานแก้แผนและกรอกผลได้ ผลรวมต้องไม่เกินยอดอ้างอิง
- **ข้อจำกัด:** แผนรายเดือนนี้อยู่ข้างแผนรายไตรมาสและแผนรายรหัสโครงการ (PL1) ไม่แทนที่ และผลที่กรอกที่นี่ไม่ใช่ที่เดียวกับผลเบิกจ่าย PL2 ยังไม่เชื่อมกัน
- **ทดสอบ (12 พ.ย. 2569):** `tests/klang.html` ผ่าน 1,217 รายการ (กลุ่มใหม่ "Request form: area, reference price register, monthly plan (Q4b)": หาพื้นที่จากชื่อและพิกัดอัตโนมัติ เตือนพิกัดนอกประเทศ สิทธิ์แก้ตารางพื้นที่ ราคาหมดอายุ/เลิกใช้/ยังไม่ถึงวันใช้ไม่ถูกนำไปใช้ สิทธิ์แก้ราคากลาง กระจายแผนรายเดือนทุกแบบและยอดรวมถูก สิทธิ์กรอกผล กดบนฟอร์มจริง: แก้แผนเดือนแรก กดกระจายเท่ากัน เพิ่มพื้นที่แล้วพิมพ์ชื่อได้พิกัดครบ) Full sweep ผ่าน 16,875 รายการ ไม่มีข้อผิดพลาด
- **ปรับ (12 พ.ย. 2569): "พร้อมส่งหรือยัง" ย้ายไปไว้ล่างสุดของแผงจัดทำข้อมูล** เป็นแผงย่อยสุดท้ายของแผง แสดงตารางสถานะรายหัวข้อ: รายละเอียดโครงการ (บอกว่ายังขาดช่องใด), วิธีจัดซื้อ, ราคากลาง, TOR, คณะกรรมการ TOR, เอกสารแนบของใบขอซื้อ (ไม่บังคับ) หัวข้อที่วิธีจัดหานั้นไม่ต้องมี แสดง "ไม่ต้องมี" ปุ่ม "บันทึกร่าง" และ "ส่งให้ผู้มีอำนาจอนุมัติ" อยู่ใต้ตารางนี้ ปุ่มส่งกดได้เมื่อทุกหัวข้อครบ **รวมรายละเอียดโครงการที่ต้องกรอกครบด้วย** (เดิมตรวจตอนกดส่ง) สถานะอัปเดตทันทีขณะพิมพ์และเมื่อใช้แผงอื่น `tests/klang.html` ผ่าน 1,220 รายการ ยังไม่ได้รัน Full sweep ซ้ำหลังการปรับนี้

### เชื่อมโยงส่วนต่าง ๆ อัตโนมัติ: เลือกแล้วส่วนที่เกี่ยวข้องตามเอง (12 พ.ย. 2569)

ตรวจส่วนที่ต้องสัมพันธ์กันในหน้าแฟ้มจัดซื้อและใบขอซื้อ แล้วทำให้เชื่อมกันเองในส่วนที่ชัดเจน (ในไฟล์ `98ze-klang-requisition.js` ท้ายไฟล์ และแก้เล็กน้อยใน `61-cases.js`, `60-procurement.js`)

**ที่เชื่อมอัตโนมัติแล้ว**
- **ชนิดงาน / เหตุพิเศษ → วิธีจัดซื้อที่ระบบแนะนำ:** เลือกอย่างใดอย่างหนึ่ง ช่องวิธีจัดซื้อเลื่อนไปตามคำแนะนำใหม่และบันทึกทันที
- **ช่องวิธีจัดซื้อและเหตุผลไม่มีปุ่มบันทึกแล้ว:** เลือกแล้วบันทึกทันที เหตุผล (เมื่อเลือกต่างจากคำแนะนำหรือมีเหตุพิเศษ) บันทึกเมื่อพิมพ์เสร็จ เงื่อนไขเดิมยังตรวจเท่าเดิม ถ้าไม่ผ่านจะไม่บันทึกและแจ้งเหตุผล
- **วงเงินที่พิมพ์ในใบขอซื้อ และราคากลาง → วิธีจัดซื้อ:** คำแนะนำอ่านราคากลาง ถ้ายังไม่มีอ่านวงเงินในใบขอซื้อ ถ้ายังไม่มีอ่านประมาณการในแผน ขณะที่วิธียังตามคำแนะนำและยังไม่ส่งใบขอซื้อ วงเงินหรือราคากลางใหม่จะเลื่อนวิธีให้เอง พร้อมแจ้งและบันทึกในประวัติแฟ้ม วิธีที่เลือกต่างจากคำแนะนำจะคงเดิม
- **ราคากลาง:** บันทึกทันทีเมื่อกรอกจำนวนและติ๊กแหล่งอ้างอิงอย่างน้อย 1 แหล่ง (ปุ่มเดิมยังใช้ได้) ค่าตั้งต้นของจำนวนคือร้อยละ 98 ของวงเงินในใบขอซื้อ และแหล่งอ้างอิงที่ติ๊กไว้ก่อนมาจาก "ที่มาของวงเงิน" ในใบขอซื้อ (ใบเสนอราคาและราคาท้องตลาด เป็นใบเสนอราคาหลายราย, ราคาที่เคยซื้อ เป็นราคาในสัญญาเดิม, ราคามาตรฐานครุภัณฑ์ เป็นบัญชีราคามาตรฐาน)
- **วิธีจัดซื้อ → TOR คณะกรรมการ ขั้นตอน e-GP ที่ต้องใช้:** ตามวิธีที่บันทึกไว้เหมือนเดิม และตาราง "พร้อมส่งหรือยัง" อัปเดตทันที
- **ระยะเวลาส่งมอบในใบขอซื้อ → วันครบกำหนดของงวดในสัญญา:** ตอนสร้างสัญญา แบ่งจำนวนวันเท่า ๆ กันตามจำนวนงวด (ขั้นต่ำ 7 วันต่องวด) ถ้าไม่มีค่า ใช้ 45 วันต่องวดเหมือนเดิม

**ที่ตรวจแล้วแต่ยังไม่ได้ทำ (ยังกรอกเอง):** ตัวเลขราคากลางจริง (ต้องคำนวณตามเกณฑ์) เหตุผลเมื่อต่างจากคำแนะนำ ขอบเขตงานในใบขอซื้อไปเป็นร่าง TOR (ยังไม่มีตัวสร้างร่าง) จำนวนและหน่วยนับไปเป็นรายการในสัญญา (สัญญายังเป็นวงเงินรวมต่องวด) สถานที่ส่งมอบไปเป็นข้อมูลสัญญา ผู้ประสานงานไปเป็นผู้ติดตามสัญญา คณะกรรมการตามหน่วยเจ้าของเรื่อง (เลือกผู้ใช้ในหน่วยเป็นค่าตั้งต้น) และการเปลี่ยนวิธีหลังใบขอซื้อส่งแล้ว (ต้องส่งอนุมัติใหม่ ยังไม่ได้ทำ)
**ทดสอบ:** `tests/klang.html` ผ่าน 1,228 รายการ (เลือกเหตุพิเศษแล้ววิธีเลื่อน บันทึกทันทีเมื่อพิมพ์เหตุผล วงเงินใหม่เลื่อนวิธี วิธีที่เลือกต่างจากคำแนะนำคงเดิม ราคากลางบันทึกทันทีและวิธีตาม แหล่งอ้างอิงตั้งต้นจากที่มาของวงเงิน) ส่วนวันครบกำหนดงวดจากวันส่งมอบยังไม่ได้เขียนข้อสอบเฉพาะ

### ชนิดงานปรับตามวิธีจัดหา TOR และคณะกรรมการ (12 พ.ย. 2569)

เดิมวิธีจัดหาผูกกับ TOR และคณะกรรมการ แต่ชนิดงาน (ซื้อพัสดุ จ้างบริการ จ้างก่อสร้าง ที่ปรึกษาและออกแบบ) ยังไม่ผูก ตอนนี้ผูกแล้ว (`98zb`, `98ze`, `61-cases.js`)
- **แม่แบบ TOR:** แม่แบบแต่ละชุดมีชนิดงาน เมื่อเปลี่ยนชนิดงานในแผงวิธีจัดซื้อ ถ้า TOR ที่แนบทำจากแม่แบบของชนิดงานอื่น ระบบเปลี่ยนเป็นแม่แบบล่าสุดที่อนุมัติของชนิดงานใหม่เอง (แจ้งและบันทึกในประวัติแฟ้ม) ตาราง "พร้อมส่งหรือยัง" แสดงว่าแม่แบบเป็นของชนิดงานอื่นถ้ายังไม่ตรง ไฟล์ TOR ที่แนบเองไม่ถูกแตะ
- **ประเภทคณะกรรมการ (CM4):** แต่ละประเภทกำหนดได้ว่า ใช้กับชนิดงานใด (ติ๊กไม่ครบ = ใช้เฉพาะชนิดที่ติ๊ก, ติ๊กครบ = ใช้ทุกชนิด) และต้องมีกรรมการที่มีความรู้ด้านช่าง/วิศวกรรมเมื่อเป็นงานชนิดใด (ตัวเลือกเดิม "งานก่อสร้างต้องมีช่าง" เป็นกรณีหนึ่งของตัวเลือกใหม่ ข้อมูลเดิมยังใช้ได้) หน้าแฟ้มแสดงเฉพาะประเภทที่ใช้กับชนิดงานของแฟ้ม และเมื่อมีประเภทเดียวกันหลายชุด (เช่น ตรวจรับทั่วไป กับ ตรวจรับงานก่อสร้าง) ใช้ชุดที่ทำเฉพาะชนิดงานก่อน ไม่มีจึงใช้ชุดที่ใช้ทุกชนิด ชุดที่ทำเฉพาะชนิดต้องไม่ซ้อนกับชุดอื่นของวิธีเดียวกัน แต่อยู่ร่วมกับชุดทั่วไปได้
- **แผงวิธีจัดซื้อ:** แสดงบรรทัด "ชนิดงานนี้มีผลกับ" แม่แบบ TOR ที่มี คณะที่ต้องมีผู้มีความรู้ด้านช่าง และประเภทที่ไม่ใช้กับชนิดงานนี้
- **วิธีจัดซื้อที่ระบบแนะนำ:** อ่านชนิดงานอยู่แล้ว (กฎวิธีจัดหา M10 ตั้งชนิดงานรายกฎได้) แต่กฎตัวอย่างทั้ง 5 ข้อตั้งเป็น "ทุกชนิด" จึงยังไม่มีกฎที่ต่างกันตามชนิดงาน ผมไม่ได้เพิ่มกฎใหม่เพราะข้อความระเบียบที่ได้รับไม่มี
- **ไม่ได้ทำ:** ข้อมูลตัวอย่างยังไม่มีประเภทคณะกรรมการเฉพาะชนิดงาน (ประเภทตรวจรับทั่วไปมีเงื่อนไขช่างสำหรับงานก่อสร้างเหมือนเดิม) ยังไม่ได้ผูกชนิดงานกับวิธีหรือแบบฟอร์มในสัญญา (เช่นงานก่อสร้างมีผู้ควบคุมงานอยู่แล้วที่หน้าสัญญา) `tests/klang.html` ผ่าน 1,240 รายการ

## รอบ Q4c: ตารางอ้างอิงรายจ่าย ประเภทงบประมาณ และหมวดรายจ่าย ตามไฟล์ที่ผู้ใช้ให้ (12 พ.ย. 2569)

- **ฟอร์มคำขอ:** เลือก **ประเภทงบประมาณ** (ว่าง = ตามรายการงบประมาณ) แล้วเลือก **หมวดรายจ่ายหลัก** จากที่อยู่ใต้ประเภทงบนั้น แล้ว **หมวดรายจ่ายย่อย** ใต้หมวดหลักที่เลือก (หมวดหลัก 800 และ 900 ให้เลือกย่อยได้ 12 แบบ) หมวดที่พิมพ์ไว้เดิมแต่ไม่อยู่ในตารางคงอยู่และติดป้าย ถ้าหมวดหลักอยู่นอกประเภทงบที่เลือกก็ติดป้ายและขึ้นเตือนในรายการตรวจ "ประเภทงบและหมวดรายจ่าย" (เตือนอย่างเดียว) เช่นเดียวกับกรณีประเภทงบที่เลือกไม่ตรงกับรายการงบประมาณ

- **ทดสอบ Q4c (12 พ.ย. 2569):** Full sweep ผ่าน 16,875 รายการ ไม่มีข้อผิดพลาด `tests/klang.html` ผ่าน 1,251 รายการ (ตรวจ: ตาราง 5 / 7 / 12 / 34 รายการ, 700 ที่ดินและสิ่งก่อสร้างอยู่ใต้งบลงทุน, หมวดย่อยตามหมวดหลัก, หมวดที่พิมพ์ไว้เดิมคงอยู่, ส่งออกและนำเข้า CSV ตามรูปแบบไฟล์ พร้อมข้อผิดพลาดแต่ละแบบ, REF_ID ใช้เป็น id, แก้แถวเดิมด้วย REF_ID เดิม)

## รอบ Q4d: ผลผลิต/โครงการ ให้มีเฉพาะผลผลิต/โครงการ/กองทุน เชื่อมกับแผนงาน (12 พ.ย. 2569)

## รอบ Q4e: ประเภทคำขอ (ปีเดียว/ผูกพัน) และดึงรายการผูกพันจากปีก่อน (12 พ.ย. 2569)

ไฟล์ใหม่ `src/js/98zi-klang-commit.js` แก้ `78-form-crud.js` (ฟอร์มสร้างคำขอ) และ `98x-klang-request.js` (ช่องประเภทคำขอ ป้ายในรายการ) `DATA_V` เป็น 61

- **ประเภทคำขอ:** ฟอร์มสร้างคำขอถามว่า **รายการปีเดียว** หรือ **รายการผูกพัน** (ค่าตั้งต้นปีเดียว) และหน้าหลักของคำขอมีช่องเลือกประเภท (เดิมมีเฉพาะปุ่มที่แท็บผูกพันหลายปี) เปลี่ยนเป็นผูกพันแล้วได้ตารางแบ่งวงเงินตามปี (ปีนี้กับปีถัดไป) เปลี่ยนกลับเป็นปีเดียวไม่ได้ถ้าปีหลังยังมีวงเงิน รายการคำขอมีป้าย "ผูกพัน" หรือ "ผูกพันต่อเนื่อง"
- **ดึงรายการผูกพันของปีก่อนที่ยังไม่ครบระยะเวลามาตั้งต้น:** ต้นแบบเก็บคำขอไว้เฉพาะปีที่กำลังจัดทำ จึงมี **ทะเบียนรายการผูกพัน (หน้า BQ6)** แยกต่างหาก: ชื่อ หน่วยงาน กิจกรรม (รหัส) งบรายจ่าย ปีแรก ปีสุดท้าย และวงเงินของแต่ละปี ปุ่ม "ดึงมาตั้งต้นคำขอปี 2571" (หน้า BQ6 และแถบเหนือรายการคำขอ) สร้าง **ร่างคำขอ** หนึ่งรายการต่อหนึ่งรายการผูกพันที่เริ่มก่อนปีนี้ สิ้นสุดปีนี้หรือหลังจากนั้น และยังไม่เคยดึง: บรรทัดเดียววงเงินปีนี้ ปีถัดไปอยู่ในตารางผูกพันหลายปี วงเงินปีที่แล้วเป็นตัวเทียบ "เทียบปีก่อน" กิจกรรมหาจากรหัสในโครงสร้างของปีนี้ เหตุผลใส่ข้อความตั้งต้น (ให้แก้) คำขอที่ดึงมาเปลี่ยนเป็นปีเดียวไม่ได้ กองแผนงานดึงทุกหน่วย สำนัก/กองดึงของหน่วยตน
- **ข้อสมมุติ/ข้อจำกัด:** ข้อมูลในทะเบียนตั้งต้น 3 รายการเป็นตัวอย่างของผม (หนึ่งรายการครบระยะเวลาแล้วจึงไม่ถูกดึง) กองแผนงานแทนด้วยรายการจริง ต้นแบบ **ไม่ได้ดึงจากคำขอหรือสัญญาของปีก่อนโดยอัตโนมัติ** ทะเบียนนี้ต้องคีย์เอง ยังไม่เชื่อมกับรายการ "ผูกพันเดิม" ของรหัสโครงการ (PJ) หรือสัญญา การดึงจะไม่ทำซ้ำรายการเดิม และเพิ่มหรือแก้ทะเบียนได้เฉพาะกองแผนงาน
- **เพิ่มข้อมูลตัวอย่าง (12 พ.ย. 2569):** ประเภทคณะกรรมการตรวจรับเฉพาะชนิดงาน 2 ประเภท (ตัวอย่าง ไม่ได้มาจากระเบียบที่ได้รับ) CTY-008 ตรวจรับงานจ้างก่อสร้าง (ใช้เฉพาะงานก่อสร้าง ต้องมีตำแหน่งวิศวกร/ผู้มีความรู้ด้านช่างอย่างน้อย 1 คน และต้องมีกรรมการที่ติ๊กว่ามีความรู้ด้านช่าง) และ CTY-009 ตรวจรับงานจ้างที่ปรึกษาและออกแบบ (ใช้เฉพาะที่ปรึกษาและออกแบบ) ทั้งสองมีกฎซ้ำซ้อนเหมือนประเภทตรวจรับทั่วไป คณะตรวจรับของแฟ้มตัวอย่างใช้ประเภทตามชนิดงานของแฟ้ม `DATA_V` เป็น 61 `tests/klang.html` ผ่าน 1,309 รายการ
- **ทดสอบ Q4d และ Q4e (12 พ.ย. 2569):** `tests/klang.html` ผ่าน 1,309 รายการ (กลุ่มใหม่ "Request kind and continuing commitments (Q4e)" ตรวจ: ฟอร์มสร้างคำขอถามประเภทค่าตั้งต้นปีเดียว, สร้างผูกพันได้ตารางปีนี้กับปีถัดไป, ช่องประเภทบนหน้าหลักของคำขอ, เปลี่ยนไป-กลับและปฏิเสธเมื่อปีหลังมีวงเงิน, ดึงรายการผูกพันได้ร่างคำขอที่ถูกต้อง (วงเงินปีนี้ ปีถัดไปในตารางผูกพัน วงเงินปีที่แล้วเป็นตัวเทียบ กิจกรรมหาจากรหัส) ดึงซ้ำไม่ได้ ที่ครบแล้วดึงไม่ได้ สำนัก/กองดึงเฉพาะหน่วยตน กองแผนงานดึงที่เหลือ คำขอที่ดึงมาเปลี่ยนประเภทไม่ได้ สิทธิ์และการตรวจของทะเบียน BQ6 และหน้าเปิดได้ รวมข้อสอบรอบ Q4d: รายการผลผลิต/โครงการไม่มีแผนงาน ทุกกิจกรรมอยู่ใต้ผลผลิต ประเภท 3 แบบ ทะเบียนมีช่องประเภท) Full sweep ผ่าน 16,945 รายการ ไม่มีข้อผิดพลาด

## รอบ Q2: ข้อสังเกตกรรมาธิการ สส/สว (12 พ.ย. 2569)

ไฟล์ใหม่ `src/js/98zj-klang-obs.js` ใช้ทะเบียนเดิม `S.observations` (เดิมมี 3 รายการตัวอย่างที่แท็บชุดชี้แจงของหน้า B6 อ่านอยู่ รายการเดิมเก็บข้อความและคำตอบไว้ และเพิ่ม เลขที่ สภา คณะกรรมาธิการ วันที่ หน่วยที่รับผิดชอบ สถานะ) หน้า **BQ7 "ข้อสังเกตกรรมาธิการ สส/สว"** แอป DPT Budget `DATA_V` เป็น 62

- **แยกสภา:** สภาผู้แทนราษฎร (สส) กับวุฒิสภา (สว) แต่ละรายการมี คณะกรรมาธิการ วันที่ประชุม ปีงบประมาณ หน่วยงานตามข้อสังเกต หน่วยที่รับผิดชอบตอบ รายการ/โครงการที่เกี่ยวข้อง ข้อสังเกต คำตอบ และสถานะ รอตอบ / ตอบแล้ว / ปิดแล้ว
- **นำเข้าไฟล์จาก สงป. (CSV หรือแท็บ):** ตรวจก่อนนำเข้า คัด **เฉพาะของหน่วยงาน** ตามช่อง "ชื่อหน่วยงานที่ใช้คัด" (ตั้งต้นเป็นชื่อหน่วยงานภาษาไทยและอังกฤษ แก้ได้) แถวที่หน่วยงานมีชื่อเหล่านี้คือของหน่วยงาน ที่เหลือถูกข้ามเว้นแต่ติ๊ก "นำเข้าของหน่วยงานอื่นด้วย" แถวที่ซ้ำกับทะเบียน (สภา คณะ วันที่ หน่วยงาน ข้อความเดียวกัน) ถูกข้าม ถ้าข้อความหน่วยงานมีชื่อหน่วยในโครงสร้าง ระบบใส่หน่วยที่รับผิดชอบให้ วันที่อ่านได้ทั้ง 2027-01-20 และ 12/1/2570 (ปีที่เกิน 2400 ถือเป็น พ.ศ.) มีปุ่ม "ใส่ไฟล์ตัวอย่าง" และบันทึกประวัตินำเข้า
- **รูปแบบไฟล์เป็นข้อสมมุติของผม** เพราะยังไม่เคยเห็นไฟล์จริงของ สงป. หาคอลัมน์จากหัวภาษาไทยหรืออังกฤษ ต้องมี สภา, คณะกรรมาธิการ, วันที่, หน่วยงาน, ข้อสังเกต (ปีงบประมาณและรายการไม่บังคับ) ถ้าไฟล์จริงต่างจากนี้ต้องปรับตัวอ่าน
- **คีย์เอง:** ฟอร์มเพิ่ม/แก้ในหน้าเดียวกัน (กองแผนงานเท่านั้น) สถานะตอบแล้วหรือปิดต้องมีคำตอบ ปุ่ม บันทึกคำตอบ ปิด เปิดใหม่ ลบ สำนัก/กองเห็นเฉพาะรายการที่มอบให้หน่วยตนและบันทึกคำตอบของหน่วยตนได้ (ข้อสมมุติ ต้องยืนยัน)
- **สรุปและส่งออก:** ตารางสรุปตามคณะกรรมาธิการ (นับตามสถานะ) และส่งออก CSV
- **ยังไม่ได้ทำ:** ยังไม่ผูกข้อสังเกตเข้ากับคำขอรายตัว (มีช่อง "รายการที่เกี่ยวข้อง" เป็นข้อความ) หน้าชุดชี้แจง (B6) ยังแสดงข้อสังเกตเดิมแบบอ่านอย่างเดียวโดยไม่แยกสภา และไม่ได้เชื่อมกับตารางตัดงบของกรรมาธิการ (PL cuts) หรือขั้นตอนรัฐสภา

## รอบ P4: ขยายสัญญา / ปรับวงเงิน 4 ขั้น (12 พ.ย. 2569)

## รอบ Q5: นำเข้าคำขอจากเอกสารด้วย OCR จำลอง (12 พ.ย. 2569)

- **ต้นแบบไม่ได้อ่านเนื้อไฟล์จริง ไม่มี OCR จริง** (หน้าเดียว ไม่มีเซิร์ฟเวอร์) เลือกไฟล์ PDF/รูปได้ (แสดงชื่อ ขนาด ชนิด และรูปตัวอย่างถ้าเป็นรูป ไฟล์แนบเป็นชื่อไฟล์ในคำขอ) แต่ "ผลอ่าน" เป็นตัวอย่างคงที่ 3 แบบที่ผู้ใช้เลือกในหน้า: **A** แบบคำของบ 1 รายการ (ราคาต่อหน่วยอ่านผิด ยอดรวมในเอกสารจึงไม่ตรงบรรทัด) **B** เอกสารเดียวมี 2 คำขอ (รหัสกิจกรรมอ่านผิดหนึ่งรายการ) **C** ภาพถ่ายคุณภาพต่ำ (ชื่อ รหัสกิจกรรม เหตุผล จำนวน ราคา อ่านไม่ได้) ทำแบบเดียวกับเอกสารจัดซื้อ (ไฟล์ 63c) ที่อ่านผลคงที่
- **ส่วนที่ทำงานจริงคือการตรวจแก้และสร้างร่าง:** ทุกช่องมีค่าความมั่นใจ ช่องที่ต่ำกว่า 80% ต้องแก้หรือติ๊กยืนยันก่อน การตรวจที่ต้องผ่านก่อนสร้าง: ชื่ออ่านออก (ไม่มี ?) มีหน่วยงาน รหัสกิจกรรมมีในโครงสร้างปีนี้ ประจำ/ลงทุนเป็น ope หรือ inv เหตุผลอย่างน้อย 10 ตัวอักษร อย่างน้อย 1 บรรทัดที่ชื่อ จำนวน ราคาเป็นตัวเลขมากกว่า 0 และยอดรวมในเอกสารต้องเท่าผลรวมบรรทัด (หรือติ๊กใช้ยอดตามบรรทัด) เอกสารหนึ่งมีหลายคำขอ ถ้าคำขอใดไม่ผ่านจะไม่สร้างสักรายการ
- **ผลที่ได้:** ร่างคำขอ (status draft) ของหน่วยงานเจ้าของ มีบรรทัดรายการ เหตุผล ประเภทประจำ/ลงทุน พื้นที่ (ถ้าชื่อตรงตารางพื้นที่ BQ4 ได้พิกัด) ไฟล์แนบ และ `r.src` บอกว่ามาจากเอกสาร ตัวอย่างที่ใช้ และจำนวนช่องที่แก้ มีประวัตินำเข้าและบันทึกตรวจสอบ (audit)
- **สิทธิ์:** สำนัก/กองนำเข้าให้หน่วยตน กองแผนงานเลือกหน่วยงานได้ (ข้อสมมุติของผม) บทบาทอื่นดูอย่างเดียว
- **ยังไม่ได้ทำ:** ไม่มี OCR จริง ไม่อ่านไฟล์ ไม่มีการสร้างผลอ่านจากไฟล์ที่เลือก ถ้าจะต่อ OCR จริงต้องมีบริการภายนอก (ต้องตัดสินใจเรื่องที่เก็บและความลับของข้อมูลก่อน) และยังไม่รองรับหลายหน้าหรือตารางหลายแถวเกินที่ตัวอย่างกำหนด
- **ทดสอบ (12 พ.ย. 2569):** `tests/klang.html` ผ่าน 1,443 รายการ (กลุ่มใหม่ "Request from a document, simulated OCR (Q5)": ผลอ่าน 3 แบบ ช่องที่มั่นใจต่ำและยอดรวมไม่ตรงบรรทัดถูกรายงาน นำเข้าถูกปฏิเสธจนแก้ แก้แล้วได้ร่างคำขอที่ถูกต้อง (บรรทัด ยอด ไฟล์แนบ ประเภท พื้นที่และพิกัดจากตาราง ที่มา ประวัติ) เอกสารที่มี 2 คำขอ คำขอหนึ่งไม่ผ่านแล้วไม่สร้างทั้งเอกสาร ภาพคุณภาพต่ำต้องเติมช่องก่อน ตัวเลขที่มีตัวอักษรถูกปฏิเสธ ติ๊กใช้ยอดตามบรรทัด กองแผนงานเลือกหน่วยงาน บทบาทอื่นนำเข้าไม่ได้ กดปุ่มบนหน้าจริงครบขั้น) Full sweep ผ่าน 17,073 รายการ ไม่มีข้อผิดพลาด ระหว่างทำ klang เคยล้มในกลุ่มของอีกเซสชัน (P2 ถึง P5) ชั่วคราวเพราะสร้างไฟล์ขณะที่เขายังเพิ่มไฟล์ใหม่ รันซ้ำหลังสร้างใหม่แล้วผ่านทั้งหมด
