# Fisko-ERP-Gov

ระบบต้นแบบระบบบริหารงบประมาณ-จัดซื้อ-การเงิน-สัญญา-ครุภัณฑ์-วัสดุ-AI ของหน่วยงานรัฐ ใช้ **Fisko** เป็นฐาน แล้วเพิ่มความสามารถตามขอบเขตของ **ERP-Government (Odoo 15, สวทช.)** ให้ครบ 8 โมดูล ข้อมูลทั้งหมดเป็นข้อมูลตัวอย่าง ไม่ใช่ข้อมูลจริง

ต้นฉบับ `Fisko-main` และ `ERP-Government-main` ไม่ได้ถูกแก้ ไฟล์นี้อธิบายเฉพาะสิ่งที่เปลี่ยนในโฟลเดอร์นี้ README เดิมของ Fisko ยังอยู่ที่ `README.md`

## วิธีรัน (ทดสอบแล้ว)

```bash
python -m http.server 8790 --bind 127.0.0.1
```

แล้วเปิด `http://127.0.0.1:8790/Fisko_Prototype.html` (ไฟล์ HTML ไฟล์เดียว เปิดตรงจากดิสก์ได้เช่นกัน แต่ลิงก์ไปเอกสาร Flow ต้องรันผ่านเซิร์ฟเวอร์หรือเปิดไฟล์ในโฟลเดอร์เดียวกัน) หน้าแรกเป็นหน้าเข้าสู่ระบบจำลอง เลือกผู้ใช้ตามบทบาท หรือสลับบทบาทจากแถบบนได้

สลับแอปจากปุ่มชื่อแอปมุมซ้ายบน มี 8 แอปตามโมดูล

| # | โมดูล | แอป | ที่มา |
|---|---|---|---|
| 1 | Organization Structure | Fisko Organization (O1 ถึง O3) บวก M10 | **ใหม่** ต่อยอดหน่วยงาน/ผู้ใช้ของ Fisko |
| 2 | Budgeting | Fisko Budget (B1 ถึง B11) | **Fisko เดิม** ไม่แก้ |
| 3 | Procurement | Fisko Procurement (P1 ถึง P13) | **Fisko เดิม** (+ รับข้อเสนอเติมสต็อกจากโมดูล 7 เป็นแจ้งเตือน) |
| 4 | Finance & Accounting | Fisko Finance (F1 ถึง F10) | **Fisko เดิม** (+ รับแจ้งค่าเสื่อม/จำหน่ายครุภัณฑ์เป็นแจ้งเตือน) |
| 5 | Agreement and Contract | Fisko Contract (C1 ถึง C4) + สัญญาใน P7 | **ใหม่** C1 ถึง C4 ใช้ข้อมูลสัญญาของ Fisko ชุดเดิม + ข้อตกลงนอกการจัดซื้อ (แนวคิด ERP agreement) |
| 6 | Assets | Fisko Assets (A1 ถึง A6) | **ใหม่** ตามขอบเขต account_asset_* ของ ERP |
| 7 | Inventory | Fisko Inventory (I1 ถึง I6) | **ใหม่** ตามขอบเขต stock_request / stock_card / stock_no_negative ของ ERP |
| 8 | AI ช่วยจัดการ | Fisko AI (X1 ถึง X3) + AI co-work เดิม | Agent เดิมของ Fisko + **ใหม่** ทะเบียนรวม และ AG-30 ถึง AG-33 |

## โมดูล HR (เพิ่มเติม นอก 8 โมดูล)

แอป Fisko HR (H1 ถึง H4): ทะเบียนบุคลากร, ใบเบิกค่าใช้จ่ายพนักงาน (อนุมัติตามขั้น O3 ผู้ขอหรือผู้ทำใบอนุมัติใบของตนไม่ได้ แล้วส่งการเงินเป็นแจ้งเตือน), รอบเงินเดือนแบบง่าย (อัตราตัวอย่าง ไม่คิดภาษีเงินได้) บทบาทใหม่ `hr` ERP-Government ไม่มีโมดูลเงินเดือน/ลา ส่วนที่ใช้ได้คือแนวคิด hr_department_code, hr_operating_unit และ hr_expense จึงเขียนใหม่เฉพาะส่วนนี้ ไม่เชื่อม Smart HR ไม่มีการลา เวลาทำงาน สรรหา ประเมินผล บำเหน็จบำนาญ ทดสอบด้วยสคริปต์แล้ว (เพิ่มบุคลากร ใบเบิกเล็ก/ใหญ่ การอนุมัติด้วยตนเองถูกกัน ส่งการเงิน รอบเงินเดือน พ้นสภาพ) และชุดทดสอบเต็มของ Fisko

## Flow ทั้ง 8 โมดูล

เปิด `Flow_9_Modules.html` (หน้าเดียว 8 ส่วน) แต่ละโมดูลมี ผู้เกี่ยวข้องและบทบาท ผังขั้นตอนแยกตามผู้ทำ ตารางขั้นตอน (สถานะก่อน-หลัง จุดอนุมัติ ข้อมูลเข้า-ออก หน้าในระบบ สถานะการสร้างและการทดสอบ) สถานะที่ใช้ การเชื่อมกับโมดูลอื่นและระบบภายนอก และสิ่งที่ยังไม่ครบ ในแอปมีเมนู "Flow ทั้ง 8 โมดูล" ที่ลิงก์ไปไฟล์เดียวกัน

ข้อมูลของ Flow อยู่ที่ `flows/data-1.js` และ `flows/data-2.js` สร้างหน้าใหม่ด้วย

```bash
node flows/build_flows.js
```

## แยกให้ชัด: ใช้ซ้ำ เพิ่ม เขียนใหม่

- **ใช้ซ้ำจาก Fisko (ไม่แก้):** โมดูล 2, 3, 4 ทั้งหมด ศูนย์รวมงาน M10 ระบบสลับบทบาท การมอบอำนาจ กฎแยกหน้าที่ AI co-work และ Agent AG-01 ถึง AG-22 เฟรมเวิร์กหน้า list + drawer (`CRUD`) และหน้าสัญญาใน P7
- **เพิ่มจาก ERP-Government:** ขอบเขตของโมดูลองค์กร ข้อตกลง ครุภัณฑ์ วัสดุ โดยอ่านรายการโมดูลใน `odoo/custom/src/addons.yaml` (operating_unit, agreement, contract, account_asset_*, stock_request, stock_card_report, stock_no_negative, base_tier_validation) **ไม่ได้นำโค้ด Odoo มาใช้ และไม่ได้รัน Odoo/Docker** กฎถูกเขียนใหม่ในรูปแบบของ Fisko
- **เขียนใหม่ในรอบนี้:** ไฟล์ `src/js/84-erp-core.js` ถึง `89-erp-ai.js`, `src/erp.css`, `flows/`, ข้อมูลตัวอย่างของบทบาทใหม่ (เจ้าหน้าที่ทะเบียนครุภัณฑ์ เจ้าหน้าที่คลังวัสดุ) และ DATA_V เพิ่มเป็น 39

หลังแก้ใน `src/js` ให้สร้างไฟล์ใหม่ด้วย `bash src/build.sh`

## สิ่งที่ทดสอบแล้ว และไม่ได้ทดสอบ

ทดสอบแล้ว (รันสคริปต์ในเบราว์เซอร์ผ่านเซิร์ฟเวอร์ข้างบน):
- เปิดหน้าใหม่ 23 หน้า และหน้าแรก ครบทุกบทบาท ทั้งสองหน่วยงานตัวอย่าง ไม่มีข้อผิดพลาดหรือค่า undefined/NaN
- ขั้นตอนใช้งานจริงแบบสคริปต์: ใบเบิกวัสดุ (ส่ง อนุมัติตามขั้นวงเงิน จ่าย จ่ายเกินสต็อกไม่ได้) รับวัสดุและราคาเฉลี่ย ปรับยอดจากการนับ (เล็ก/ใหญ่) ครุภัณฑ์ (รับเข้าจากสัญญา ยืนยันขึ้นทะเบียน โอนพร้อมอนุมัติและรับ ขอจำหน่ายและอนุมัติ ตรวจนับและปิดรอบ ปิดงวดค่าเสื่อมและแจ้งการเงิน) ข้อตกลง (ร่าง ส่ง อนุมัติโดยบทบาทที่ถูกต้อง บอกเลิก) หน่วยงาน ตำแหน่ง ขั้นอนุมัติ และ Agent AG-30 ถึง 33
- ชุดทดสอบเดิมของ Fisko (`tests/run.html`) รันแบบเต็มในโฟลเดอร์ใหม่ (ทุกบทบาทรวมบทบาทใหม่ ทั้งสองหน่วยงาน ไทย/อังกฤษ แชท Agent และเดโม): ผ่านทั้งหมด 12,625 รายการ ไม่มีข้อผิดพลาด ใช้เวลา 99 วินาที

ยังไม่ได้ทดสอบ:
- การแสดงผลบนมือถือและโหมดมืดของหน้าใหม่ (ใช้สไตล์เดิมของ Fisko แต่ไม่ได้ตรวจตา)
- การกดสวิตช์เปิด/ปิด AG-30 ถึง 33 ที่ B11
- การทำงานทางลัดบนแป้นพิมพ์และการใช้ screen reader ของหน้าใหม่
- การเชื่อมระบบภายนอก สงป. GFMIS e-GP KTB Smart HR น้องก่อ ทั้งหมดยังเป็นไฟล์หรือจำลอง หรือยังไม่มี

## ข้อจำกัดสำคัญ

- Agent ทุกตัวเป็นการจำลองด้วยกฎ ไม่ได้เรียกโมเดลภาษา ไม่อนุมัติ ไม่จ่าย ไม่ลงนามเอง
- หมวดครุภัณฑ์ อายุใช้งาน เกณฑ์ต่ำกว่า 5,000 บาท และเกณฑ์ขั้นอนุมัติ (100,000 / 20,000 / 10,000 / 500,000 บาท) เป็นค่าตัวอย่าง ต้องตรวจกับระเบียบจริง
- ค่าเสื่อมราคาคำนวณในต้นแบบเท่านั้น ไม่ลงบัญชีจริง ส่งเป็นแจ้งเตือนไปที่หน้าปิดงวดของการเงิน
- วัสดุ: ไม่มีหลายคลัง ล็อต วันหมดอายุ จ่ายบางส่วน ใบเบิกมีได้ 3 รายการ ใบรับ 2 รายการ
- ข้อมูลเก็บใน localStorage ของเบราว์เซอร์ ปุ่ม "รีเซ็ตข้อมูล" ที่ท้ายเมนูซ้ายคืนค่าตัวอย่าง
